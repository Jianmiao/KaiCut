# Native command contract

The Rust session is the authoritative project state. Frontend calls these Tauri commands with `invoke` and replaces its project projection with the returned session. All project commands serialize access to the session. Native pickers and confirmations execute outside the async runtime worker.

## Shared result

### Opt-in native source preview (2026-10-18)

On Windows, the `native-preview-host` feature and both runtime flags `--native-preview-host --native-source-preview` enable source selection and controls. Default launches, timeline playback, images and audio-only assets keep their existing paths. These commands do not change `.kaicut`, undo history or dirty state, and do not add MCP tools.

| Tauri command | Arguments | Runtime contract |
| --- | --- | --- |
| `native_source_capability` | none | Return `{enabled}`; false without the feature/platform/runtime flags. |
| `native_source_open` | `{request:{projectId,revision,mediaId,requestId}}` | Main window only. Resolve the imported video from Rust's authoritative session; frontend paths are not accepted. Probe in the background and return `supported:false` with reason/diagnostic, or an owned token with duration, position and phase. |
| `native_source_cancel_open` | `{request:{projectId,revision,requestId}}` | Main window only. Mark only this registered preparation cancelled without waiting for the owner. Return `{cancelled,pending,token?}`; an accepted cancellation is not completion. A known old-context request may be cancelled after project/revision changes; unknown stale identities cannot create cancellation records. |
| `native_source_control` | `{request:{token,action,positionNs?}}` | Main window only. Actions are play/pause/seek/close. Seek is an integer decimal nanosecond string in `[0,duration]`, including EOF. An obsolete close is harmless to the newer owner; other obsolete controls fail. |
| `native_source_status` | `{token}` | Main window only; require the current token and recheck project/media context. Report runtime state without changing the project. |

The first source profile admits one video stream plus one 48 kHz stereo AAC stream in MP4/MOV, at most 60 seconds, 512 MiB and 1920x1080, with explicit square pixels and no rotation/display matrix. Decoded PTS/sample counts establish origin and EOF; source files are identity-checked and held against writes/deletion during use. Audited sidecar hashes are mandatory, with fixed checkout or executable-sibling locations only; no PATH, shell or network protocols. Probe output, allocation, frame counts and individual timeouts are bounded. This is a development admission profile, not a project schema restriction or a guarantee for all codecs/HDR/network-mapped drives.

The background owner serializes session replacement and token control; a generation check before replacement prevents stale opens from closing newer owners. The frontend waits for host attachment, serializes status/control, coalesces pending seeks and discards late responses. Source playback has no diagnostic PCM capture or GPU readback; bounded rolling state replaces the diagnostic two-second capture limit. EOF requires decoder completion, final frame acceptance and output drain; exact-end seek holds the last frame without starting audio, and Play after ended seeks to zero. Close joins the actor before closing/unbinding its sink; app exit waits off the event thread. Compatibility fallback mounts HTML media only after confirmed native close; failed close keeps an error state instead of starting a second player. Hidden validation forces its own audio session muted and does not change system volume.

Open registration, generation changes and the first exit decision now share a short-held lifecycle gate. Exit seals registration even while idle; earlier requests retain RAII opening guards until retired. No gate lock is held while waiting for the owner, UI or actor. First-exit observations are preserved independently of the current retirement counters; they are runtime diagnostics, not persisted project data.

Six additional hidden instances passed rapid A/B/A overlap and normal application exit during preparation/playback (two each), with a same-build nine-step source-control regression. That batch observed preparation exit before actor construction; later initialization and fault batches are documented below. Source command observations are enabled only by the hidden debug validation entry point, retain at most 128 records and fail evidence validation on overflow. They pass through original command results and do not add an external control surface. See `docs/NATIVE-SOURCE-STABILITY.md`; visible display and physical input/output sync remain separate gates.

The source actor checks decoder errors and nonzero child exits while ready or paused, so bounded queue backpressure cannot hide a dead decoder until Play. `DecoderShutdown.cleanupErrors` separates teardown failures from retained original decode errors. `AudioTransfer` preserves the first close result across retries; it never converts a failed cleanup into a null successful report. Runtime close confirmation requires stopped audio, joined/reaped decoder, empty cleanup error ledgers, a closed/drained sink and successful unbinding. A failed confirmation leaves a process-local failed-token record; repeated close still fails and blocked opens return that token, keeping the frontend in error rather than starting a second player. Restart is required after this conservative failure state.

Six hidden instances validated seek/source overlap, owned RGB-decoder termination while paused and a one-shot error before WASAPI initialization, followed by compatibility fallback and fresh native recovery. Injection only arms inside the explicit hidden debug validation entry point; no external PID or system device setting is accepted. The device case creates real decoder processes but never attempts device open, so real hardware failure handling remains unqualified. See `docs/NATIVE-SOURCE-FAILURES.md`.

Preparation now checks request cancellation and generation between profile stages, every 64 KiB hash read and while an owned probe runs. Probe cancellation terminates only the held private process and joins stdout/stderr readers before settling the open. Bounded request records handle cancellation arriving before registration, reject duplicate/over-limit opens without invalidating newer work, and retain preparation/cleanup evidence independently of the owner lock. Unconfirmed probe teardown enters the same failed-close protection as an active player. Frontend cancellation waits for the original open to settle and closes any returned token before compatibility fallback. Cancel acknowledgement, absence of a child surface and process exit remain separate facts.

Two hidden runs each covered cancellation to an empty timeline, replacement during a running probe, and an injected cleanup-confirmation error after actual successful unbinding. The last case verifies the failed-token/error-state path without deliberately leaking resources, not physical Stop/Reset/COM failure. See `docs/NATIVE-SOURCE-CANCELLATION.md`. No new MCP tool or project schema field was added.

Request-scoped cancellation now extends through decoder creation, before/after device open, adapter/scheduling construction and the initial preparation loop. Cross-thread callbacks own the exact request identity and cancellation/generation checks; no registry or lifecycle lock is held while waiting. Observations record actual acquired resources before checking cancellation. Successful initial preparation removes these opening callbacks so later Play/Seek cannot be cancelled by an obsolete opening generation; runtime readiness still rechecks the opening lease before publishing it.

`SourceStartError` retains the primary initialization error, actual worker join result and raw cleanup report. Adapter constructor failures also return teardown evidence. Runtime cleanup independently requires joined/reaped created decoders, released opened devices, no audio Start during failed initialization, drained/closed sink and successful unbinding. A partial resource acquisition lacking cleanup proof enters failed-token protection, even if normal RAII release was attempted; it must not be represented as an unsupported profile eligible for immediate HTML fallback. System/COM calls are checked before/after, not forcibly interrupted.

Six hidden instances validated cancellation after actual WASAPI open, cancellation after the first prepare tick and normal exit during that tick (two each). Only the explicit hidden debug validation path adds a bounded checkpoint hold; timeout fails validation. The hold is controlled scheduling, not a driver fault or natural cancellation-latency measurement. All six observed native invocation completion; four cancellation runs recovered to a new source and played. Initialization cleanup lacks a direct profile fingerprint, explicitly retained as an evidence limitation. See `docs/NATIVE-SOURCE-STAGE-CANCELLATION.md` for raw identities, same-build regressions and remaining gates.

The hidden validation path also holds one real non-diagnostic `present_media` completion after the platform call returns and before the queue publishes its acknowledgement. A background call through the existing native source-control wrapper must remain pending while `close` closes the sink or `seek` advances the render epoch; after explicit release, the same completion is recorded as `Closed` or `Stale`, never as a current published ACK. Four instances (two per scenario) recovered playback and cleanup. This proves post-call retirement ordering and late-result classification only; it cannot interrupt a Present already executing in the driver. The validator records this boundary in `docs/NATIVE-SOURCE-INFLIGHT-RETIREMENT.md`.

Before calling the native renderer, the sink also rechecks its terminal error, closed state and queue/job/frame render epochs. A job already obsolete at that check is counted in `skippedBeforePresent` and its bounded `skippedEvents` ledger; it does not call the platform renderer or publish a MediaAck. Skips and actual Present/blocked results are separate, with no fabricated HRESULT or acceptance. New-epoch pending work remains scheduled. The queue mutex is released before any driver call, so retirement after the last check still relies on post-call rejection. Hidden before/after checkpoint scenarios cannot claim each other's callbacks. Abandoning a validation disarms an unclaimed checkpoint or releases a held callback with failed evidence. See `docs/NATIVE-SOURCE-PRE-SUBMISSION.md`; a normal-control regression also recorded one unresolved underrun before a same-program repeat passed.

Each native audio segment now retains at most 16 typed Start records and 16 pre-pump underrun records with total/dropped counts. Runtime snapshots expose summaries; final segment reports hold the events. Start timing measures `AudioPreviewAdapter::start`, with call duration and first-pump delay from return separately recorded. The existing zero-padding/nonzero-remaining predicate is unchanged and shares its observation with diagnostics. Underrun clock sampling is best effort, does not replace playback errors and does not acquire decoder-statistics locks; reserved pending frames do not prove PCM availability. Hidden `underrun-delay` is an explicit one-shot positive control at the target segment's first pump, requesting three buffer durations (60–250ms), with actual overshoot reported. It is not a natural fault or an elapsed-time bound. Three normal runs and two positive controls validate this telemetry; the earlier intermittent natural underrun remains unresolved. See `docs/NATIVE-SOURCE-UNDERRUN-DIAGNOSTICS.md`.

The hidden `audio-tail-stress` scenario executes exactly six DOM seeks to 200ms before the source endpoint, each followed by a new Ready generation, one Start and natural EOF. Four isolated processes form the fixed 24-Start experiment. It adds no artificial delay or playback parameter changes and does not stop or retry on an underrun. Completed evidence and zero-underrun outcome are separate fields; seven retained segments and an untruncated event/decoder ledger are required. This batch observed zero underruns but does not resolve the prior intermittent event or qualify other media/devices. See `docs/NATIVE-SOURCE-TAIL-STRESS.md`.

The hidden `audio-span-stress` scenario is a fixed development validation sequence: pause around 5s, hold the cached paused state for 150ms, resume to EOF, seek/play/pause at 10s, seek/play/pause at 1s, then seek to 200ms before EOF and play to EOF. The fixed fixture is 20,010,666,666ns with 600 video frames, 938 AAC frames and 960512 decoded samples. Two isolated runs passed with zero natural underruns. Each segment retains bounded Start/underrun ledgers; the first segment must contain two Start records at source epoch 1 and the three seek segments one Start at epochs 2, 3 and 4. Critical lifecycle events are capped at 64; the 128-entry video trace is rolling. The pause hold compares cached state and pump count only, not a fresh device-clock sample. This remains hidden, muted development evidence and does not establish visible output, audible quality, physical A/V sync, long-media or cross-device qualification. See `docs/NATIVE-SOURCE-SPAN-STRESS.md`.

Actor Cancel/Finish acknowledgements reject recorded cleanup failures without overwriting the primary playback error; Finish still joins and returns the full report. Cancelled devices never resume pumping or busy polling after an unsuccessful Stop. Observe retains real device-clock reads after successful cancellation, but does not sample a cancelled device whose cleanup remains unconfirmed. Surface unbinding retains its exact Weak owner until suspension and state observation succeed; even an expired Weak blocks a new binding until release is confirmed. Cleanup confirmation also rejects an existing failed or incomplete `lastCleanup`, so an empty binding cannot erase a prior frontend surface-release failure. Final no-child exit reports preserve the previous raw release result.

Two isolated hidden instances exercise a one-shot error before the actual suspend call, repeated failed closes and blocked B selection; this is an application-boundary injection, not a COM or hardware failure. The frontend may destroy A's child and briefly construct/destroy B's empty view while no B actor exists. Each child must have its own destruction evidence. Stop/Reset failure behavior is separately tested with a controlled output backend. See `docs/NATIVE-SOURCE-CLEANUP-ERRORS.md`; system devices are not changed and real device-loss qualification remains open.

### Existing diagnostic entry points

The hidden `--native-media-check-dir <target directory> --native-media-fixture-dir <controlled fixtures>` path connects actual FFmpeg-decoded RGB and an owned muted WASAPI clock to the existing Tauri child surface. It requires the native-preview-host feature/runtime flag plus the isolated hidden debug validation flags. It is not a user-selected media playback command: ordinary source/timeline transport still uses WebView. The actor owns decoder/device creation, packet supply, clock sampling, pause, seek and cancellation on one background thread; no PCM or RGB is sent over frontend IPC. Main-thread delivery has at most one pending native RGB frame and one executing callback. Old generations reject or discard work, but cannot revoke a Present already entered; control validation waits through a main-thread barrier before claiming no further old calls.

`render_source_and_present` accepts source dimensions independently of the swap-chain extent. A cached source texture and integer point-sampling shader fit square-pixel RGB into the target with opaque black bars; source and target are currently bounded to 1920x1080. CPU RGB-to-RGBA upload remains, so this is not zero-copy. Only explicit preparation frames read back the actual fitted backbuffer. Ordinary frames preserve source hashes and raw Present status without readback. Layout updates in media mode resize/hide the child and wait for a new decoded frame instead of drawing a calibration image. A blocked overlay rejects native frame submission while audio continues. This batch resizes while audio is paused; running resize, display cadence, audible output and physical sync remain separate tests.

The actor exposes bounded internal prepare/play/pause/seek/observe/cancel/finish controls to the background validator. Readiness requires audio prefill plus a matching accepted diagnostic frame and an observed future video PTS; EOF preparation is not supported by this development path. Cancel stops/resets output and invalidates frames while retaining fresh device-clock observation until Finish joins the thread. Report capture is limited to eight segments, two seconds of accepted PCM per segment, 1024 main-thread frame events and 16 diagnostic images. Actual decoded-reference hashes, accepted PCM bytes, fitted source/target images, all seek child-process exits and final HWND cleanup are verified independently. See `docs/NATIVE-TAURI-MEDIA.md` for the bounded tested scope.

The optional `native-preview-host` feature plus `--native-preview-host` enables a calibration-only child surface in the actual main Tauri window. Normal builds/runs return `{enabled:false,sessionId:null,revision:0}` from `native_preview_host_status` and allocate no child/device. The enabled status exposes a process-local session ID and monotonically increasing request revision. `native_preview_host_layout({request})` accepts only main-window requests with that session, a new JavaScript-safe sequence and finite CSS geometry whose viewport and scale match the native client. `native_preview_host_release({sessionId,sequence})` releases the owned child without changing project state. Stale sessions/sequences reject before changing current state; malformed current geometry hides the calibration surface. These diagnostic controls are not a playback backend or a persisted setting.

The frontend observes the preview content box, subtracts padding/control overlap, clips to viewport/overflow ancestors and submits at most one in-flight plus one pending update. Popovers, dialogs, errors and ancestor animation suspend native coverage. Resize/DPI notifications hide stale native coverage and request a fresh frontend measurement. All native construction, drawing and cleanup run on the Tauri event-loop thread. The child HWND is a clipped sibling above the WebView, without activation/tab-stop, and answers HTTRANSPARENT/MA_NOACTIVATE; these same-thread hit-test responses are not proof of real pointer or keyboard behavior. Owned-child WM_DESTROY attempts graphics cleanup independently of the outer TLS borrow; unexpected COM reentrancy is explicitly failed and reported, not described as guaranteed early cleanup. Main-window destruction and application exit also release the host.

`ui_*` MCP responses include `nativePreviewHost` status, which is disabled in ordinary runs. UI inspection may be requested before frontend event listeners are ready; clients may retry read-only inspection after startup, but must not blindly replay edits. The hidden validation requires a debug build and `--mcp --mcp-hidden --mcp-validation --native-preview-host --native-preview-check-dir <new target directory>`. It uses actual built WebView DOM and native HWND state while changing only the isolated window/layout. Reports separately identify calibration, simulated DOM overlays, actual Tauri resize, parent destruction and absent screen/media-playback evidence. See `docs/NATIVE-TAURI-PREVIEW.md`.

`native-preview-surface` exposes the device-independent `SurfaceLifecycle`. Attachment, layout and detachment reserve generation-bound tickets; only matching successful completions update confirmed layout. Invalid logical sizes, scale factors, stale callbacks and failed operations cannot silently change the last confirmed extent. Physical sizes use ceil(logical * scale), bounded to 1920x1080; zero area or an explicit minimized flag suspends frame permission. Hidden visibility is a separate host observation, not minimization. Closing is terminal and invalidates pending work.

`native_surface_probe` (`native-surface-probe`) binds the existing composition swap chain to an owned, always-hidden top-level HWND via a same-device DirectComposition visual/target and a real Commit. It is not a Tauri/WebView attachment or public application command. The window has no WS_VISIBLE, uses NOACTIVATE/TOOLWINDOW/NOREDIRECTIONBITMAP, and never calls ShowWindow or foreground/focus APIs. Its owner verifies native visibility, process/thread identity and client dimensions; resizing uses NOACTIVATE/NOZORDER/NOMOVE. A scoped per-thread DPI-awareness context is restored on teardown. Binding only accepts a live same-process HWND; the caller still owns its lifetime and must detach/drop graphics before DestroyWindow on the creating thread. Attach/detach preserve actual Commit HRESULT values; successful API submission does not establish compositor or screen completion. The diagnostic exercises logical 100/150/200 percent scaling, two suspended layouts, reattachment and terminal closure. Minimize and DPI-transition inputs are simulated; no actual OS minimize or monitor transition is asserted. See `docs/NATIVE-SURFACE.md` for actual evidence and remaining integration work.

`native_av_present_probe` is a separate opt-in diagnostic (`native-av-present-probe`) that connects the existing audio-device clock and source selector to a thread-owned composition presenter. The bounded worker admits two pending RGB frames, one in-flight job and one latest result; audio submission/polling use nonblocking queue access. Only preparation frames request backbuffer readback, and audio starts after an exact diagnostic frame with an accepted Present result. Ordinary frames retain source identity and raw Present status without GPU readback. A busy result is not readiness or acceptance: the next producer tick may resubmit the latest eligible frame, while a delayed busy result cannot erase a newer queued index. Queue-lock contention and DXGI busy are separate counters. Stop audio before retiring a render epoch; retirement invalidates queued/results and waits for reserved in-flight calls before confirming idle. It cannot retract a driver call or prove GPU/compositor completion. Cancel additionally checks that known Present calls stop increasing after retirement. The optional 0–120ms worker delay exercises queue pressure, not real DXGI busy. Backend-call reservations, successfully returned Present results, consumed results and pixel-verified frames are distinct counts; a backend error can leave actual Present occurrence unknown. The probe creates no HWND/visual or public app command, does not attach to the main player, and uses only its owned muted WASAPI session. See `docs/NATIVE-AV-PRESENT.md`.

`native_present_probe` is an opt-in diagnostic example requiring `native-present-probe`. A thread-affine hardware D3D11 owner creates an unattached DXGI composition swap chain (RGBA8, two buffers, flip sequential, stretch, single sample, opaque alpha). It creates no HWND, composition visual/target, audio device or application command. Each submission renders into the actual current backbuffer and invokes `Present(0, DO_NOT_WAIT)` while preserving the raw HRESULT. `S_OK`, busy, occlusion, other positive statuses and failure remain distinct; none is proof of screen display. Only explicit diagnostic frames copy/map the actual backbuffer for exact content validation; ordinary submissions do no readback or GPU-query wait, but still convert/upload CPU RGB. A pure gate rejects obsolete epochs, resize-in-progress, suspension, failure and closure. Zero extent suspends without Present/ResizeBuffers or a fabricated success HRESULT. Nonzero resize releases frame-local texture/view references and context bindings before ResizeBuffers, then recreates size-dependent resources while retaining the device/shaders. Failed resizing is terminal. Reported descriptors are requested/configured values, not GetDesc1 observations; releasing Rust-owned resources is not proof of immediate VRAM reclamation. The main WebView player and `.kaicut` contract are unchanged. See `docs/NATIVE-PRESENT-PROBE.md` for actual API-submission evidence and remaining display qualification.

`native_stream_probe` is another explicit, non-default diagnostic (`native-stream-probe`). It reuses the audited sidecars without adding codecs: one RGB FFmpeg pipe, one integer-frame-timestamp ffprobe pipe and one PCM16 WAV FFmpeg pipe. Bounded input queues hold at most four 160×90 RGB frames and eight blocks of 480 audio frames; playback polls without waiting for decoder queue data. Session callbacks are epoch-checked; readiness requires actual endpoint prefill and decoded video, and EOF requires source completion plus output clock/drain. Seek currently restarts and sequentially discards source data, not indexed random access. Pause preserves decoder buffers and invalidates renderer work; seek/cancel stop/reset audio and kill/reap only owned children before joining readers. A separate reference verifier runs after playback. This adds no public Tauri/MCP command, persistence field, visible window or Present path. See `docs/NATIVE-STREAM-PROBE.md` for tested fixture/device limits and actual evidence.

The same diagnostic accepts `--audio-scheduling poll|event|event-mmcss` (default `poll`). Event-driven shared audio uses zero requested buffer duration/periodicity as required by IAudioClient, binds an auto-reset readiness event before Start, and reports the actual endpoint capacity. Running waits are bounded; a timeout/error is reported instead of silently switching to polling. The MMCSS variant registers only the current playback thread with the Audio task at normal relative priority, explicitly reverts on every phase exit, and retains a thread-affine cleanup guard. Renderer shutdown separately records work-loop exit, backend destruction, worker exit marker and join wait. These timings do not prove a hard driver deadline, leak freedom or physical audio/display synchronization. See `docs/NATIVE-EVENT-AUDIO-PROBE.md`.

`--renderer-lifetime scoped|shared` (default `scoped`) controls diagnostic GPU ownership. Playback borrows a worker from an outer owner; cancellation stops/resets audio, closes decoder children and retires the render epoch. Retirement must confirm pending/latest/in-flight are empty and the worker is healthy before reuse; it does not destroy the GPU backend. The shared owner persists across the two cases and closes once at the end, including errors. The scoped owner closes after each case. A stable owner/backend UUID and cumulative counter snapshots distinguish reuse from reconstruction; the UUID is not a physical adapter identity. `--long-playback partial|full` (default `partial`) chooses partial or complete 20-second fixture playback; full EOF also requires verified frame 599. Trace capacity is explicitly 16384 records per case; phase deadlines are controlled fixture duration plus eight seconds. Session cancellation and final GPU release are separately reported. No main-application ownership or playback backend changes. See `docs/NATIVE-REUSE-PROBE.md`.

`--hd-fixture-dir` selects the controlled 1920×1080/30fps/60-second profile and requires a release build plus explicit `shared` renderer and `event-mmcss` audio modes. It creates one HD session, consumes the complete source with a pause/resume checkpoint, then restarts decoding for a 30-second source seek and cancellation. `StreamConfig` accepts checked output dimensions up to 1920×1080; decoder stats retain source/display/coded dimensions, frame bytes and queue byte high-water. The HD driver requires the actual source and output to both be 1920×1080. A source-hash-bound reference ledger of at most 2 MiB contains 1800 integer-PTS and RGB/RGBA hash records; completed results are verified after playback without loading a whole raw movie. EOF requires 2,880,000 submitted PCM frames, clock coverage through 60 seconds, zero output padding and verified video index 1799. Functional success, feed-budget success and realtime qualification remain separate. This is offscreen readback diagnostics, not a presentation implementation; dropped jobs and render completion gaps must be reported. See `docs/NATIVE-HD-PROBE.md`.

The probe additionally accepts `--seek-mode sequential|indexed-cfr` (default sequential). Indexed mode admits only zero-origin 30/1 video with an exact frame timebase and native 48 kHz stereo PCM16 WAV. It input-seeks FFmpeg to a preceding frame anchor and filters earlier ffprobe interval timestamps before pairing RGB; every observed integer PTS must occupy consecutive positions on the admitted frame grid. Fractional-nanosecond frame positions are inverted using checked integer arithmetic, not floating-point seconds. Audio input seeks to a whole second and discards the exact remaining sample frames. Source cursor offsets and actual frames read are separately reported. Unsupported inputs fail explicitly; there is no silent fallback. `--seek-only true` limits the HD diagnostic to the initial two seconds and the 30-to-31-second seek interval, so it must not be reported as full 60-second playback. Seek timings include decoder start and complete stop-to-prepared duration separately from final prefill. The exact first prepared and first GPU-verified target frame must match frame 900. No main-app or public Tauri/MCP command changes. See `docs/NATIVE-SEEK-PROBE.md`.

`native_compat_probe` is a separate decoder-only example under `native-stream-probe`. It explicitly uses `SeekMode::IndexedPts`: a fresh source-fingerprinted full decoded-PTS index is limited to 100000 entries and 8 MiB JSON, with a bounded subprocess deadline. The selected frame is the actual preceding timestamp, normalized against the first decoded frame while input seek uses an absolute source timestamp. Every streaming timestamp must match the full index, including reordered-frame and nonuniform-interval sources; negative absolute anchors are rejected by this adapter. Input source fingerprints are checked around index construction and before/after matrix verification. Native PCM may input-seek exactly; AAC/M4A is admitted only here and always decodes from origin before sample-accurate discard. The full decoded PCM reference defines actual tail length; metadata duration and packet priming are not subtracted again. The matrix creates no GPU or audio endpoint and adds no project schema, public command or UI behavior. See `docs/NATIVE-COMPAT-PROBE.md`.

`native_audio_timing_probe` adds a decoder-only fixed-window timing check. `AudioTimeline` consumes actual first-decoded audio/video PTS with rational timebases and actual decoded PCM frame count. It computes a signed relative origin, snaps the block's first query to the last floored sample PTS at or before that time, then advances consecutive source samples. An early block receives leading silence; crossing source EOF receives trailing silence; all parts sum to the requested frame count. It supports checked 8–192 kHz arithmetic, at most 24 hours and 4800 frames per request; actual fixtures currently cover only native 48 kHz stereo. Continuous transport must retain an integer sample cursor and must not independently requantize each block. Codec priming already handled by decoding is not subtracted again. Aperiodic source/reference samples and separate channel hashes validate real source windows; no audio endpoint, GPU, project field or application command is introduced. See `docs/NATIVE-AUDIO-TIMING.md`.

`native_audio_transport_probe` connects that placement to a persistent integer `AudioCursor` and bounded PCM assembler. `reserve` creates one pending ticket without advancing output; `commit` consumes only the accepted prefix. Every positive partial commit rotates the pending ticket ID; zero acceptance changes nothing, and duplicate or stale IDs/epochs fail without mutating state. Pause preserves pending data, seek invalidates it and rebuilds only the new decoder session, and cancellation is terminal. `AudioTransfer` retains at most one prepared 4800-frame packet plus the remaining decoded block; it does not recreate the decoder per packet. Output is bounded to 24 hours per cursor anchor. Offline diagnostics vary requests and acceptance lengths and retain bounded raw PCM captures; explicit `--device true` validates one owned muted event-driven WASAPI stream with MMCSS and actual partial writes. Capture records submitted bytes, not physical speaker output. This adds no main-app command or backend change. See `docs/NATIVE-AUDIO-TRANSPORT.md`.

`native_audio_session_probe` exercises `AudioPreviewAdapter<TransferBackend, OutputBackend>` against a single owned muted WASAPI output. Preparing fills the endpoint and prepares the next bounded PCM packet before Ready; preparation does not start playback. New packet requests are capped at endpoint capacity, and each write is capped at the observed writable capacity and caller request. Only actual accepted samples advance the cursor. Pause stops without resetting queued data. Seek stops/resets the output, invalidates the transfer epoch and reopens the decoder, returning Preparing without automatic playback. Cancel stops/resets/closes and rejects all later playback requests. Backend failures retain the primary error and attempt every cleanup step; post-write acknowledgment failure also clears queued data. Explicit cancellation can enter Cancelled while retaining previous failure/cleanup evidence, never reviving playback. Read-only output access is diagnostic; capture is accepted input and may include samples later discarded on seek/cancel. No public application command or backend replacement is added. See `docs/NATIVE-AUDIO-ADAPTER.md`.

`native_av_session_probe` combines that adapter with shared decoder video selection and the offscreen renderer. `AudioTransfer::new_av` preserves a current and one future frame; default audio-only construction still drains unused video. `video_frame(project_ns)` returns the latest observed due frame, polls at most eight frames and never returns a future PTS; exact first-frame preparation requires an independent source-reference check. Seek resets both retained frames and the source epoch. The coordinator maps project time as target plus raw device position divided by its own clock frequency, not accepted PCM progress. The first verified GPU result must precede audio Start. During playback GPU completion is polled without waiting; pause/seek/cancel stop audio before waiting for render retirement. Every completion rechecks render/source epochs and source hashes. New PCM requests also honor the transfer's preferred 480-frame decode quantum, alongside endpoint/caller limits, to avoid waiting for a larger assembled block. This adds no normal-app command, visible window or Present path. See `docs/NATIVE-AV-SESSION.md`.

`native_queue_probe` is a non-default diagnostic example requiring `native-queue-probe` (which also enables `native-d3d-probe` and the pure `native-preview-queue` module). The WASAPI owner submits bounded RGB frame references through a nonblocking queue; a dedicated worker creates, uses and drops its D3D renderer on that thread. There are at most two pending jobs, one in-flight job and one latest completed result. Full queues evict the oldest pending job; lock contention drops the current submission with a counter. Pause, seek and cancel invalidate the render epoch and queued results. Publication rechecks epoch/closed under the same lock; terminal errors cannot be overwritten by a newer completion. Shutdown stops audio before closing and joining the renderer, without claiming a hard timeout for a stuck OS driver call. Each playback phase must consume a verified frame matching its current render epoch and decoded index/PTS/hash. This adds no app command, MCP tool, project field, swap chain or Present path. See `docs/NATIVE-QUEUE-PROBE.md` for ordinary and artificial-delay device evidence.

`native_d3d_probe` is another non-default diagnostic example requiring `native-d3d-probe`. Media/clock lifecycle is shared through `examples/support/native_media_driver.rs`; the media-only entry calls it with graphics disabled. The D3D entry requires a hardware D3D11 adapter, renders uploaded decoded RGB through fixed shaders to an RGBA8 UNORM render target, copies to staging, waits for an EVENT query and maps rows using the actual RowPitch. Asymmetric calibration and every selected frame have exact pixel/hash validation. There is no swap chain, Present or desktop window. CPU upload-to-readback timing and paired post-render audio-clock samples are diagnostic observations, not display timestamps. No normal app startup, project command or MCP tool enables this path.

`native_media_probe` is a separate opt-in example (`native-media-probe`, depending on `native-clock-probe`). It decodes bounded generated fixtures with the audited checkout sidecars into PCM16 WAV and RGB frames paired with actual best-effort integer timestamps. The adapter supports explicitly recognized float32/PCM16 endpoint mix formats, submits decoded samples with render flags 0, and mutes only its own unique nonpersistent audio session. PCM mode requires prequeued samples and never substitutes silent tail packets. EOF validation requires both no queued frames and the output clock reaching the decoded source end; this still does not measure physical speaker drain. Reset creates a new epoch and source cursor; queued pre-seek/cancel data cannot survive. Selected decoded video frames are not yet submitted to D3D or the app. No new public Tauri/MCP command or project-schema field is introduced.

`native_clock_probe` is an opt-in diagnostic example, built only with the non-default `native-clock-probe` feature. It is not a Tauri command or MCP tool and is not enabled by normal application startup. It opens a thread-affine shared-mode silent WASAPI render stream, reads raw audio device positions and their own frequency, and exercises Stop/Resume/Reset plus a pure epoch-based project-clock mapper. Its generated video PTS ledger is not a decoded or presented video stream. No project schema, existing preview backend, capture permission, default output device or system volume setting is changed. See `docs/NATIVE-CLOCK-PROBE.md` for the explicit CLI and evidence limits.

Project commands return `{ project, path: string | null, dirty: boolean, status: string, revision: number, canUndo: boolean, canRedo: boolean }`. `project` uses schema version 2 from `src/types/project.ts`; media references may include `sourcePath`. Clips are persisted with `id/mediaId/trackId/startFrame/durationFrames/sourceInFrame/sourceDurationFrames/fadeInFrames/fadeOutFrames`. Audio tracks persist `volume` (linear gain 0..1) and `muted`; old v2 files missing these fields use volume 1 and zero fades. All frame fields use the project rational timebase at 1x speed. Media bytes, URLs, probe/thumbnail state, selection, playhead and history are not persisted. New projects have two empty video and two empty audio tracks. Timestamps are RFC 3339 UTC strings.

Errors reject the Tauri command with a user-readable string. Cancelling a picker or declining a discard confirmation resolves to the current session with a cancellation status; it does not replace the project, clear dirty state, or change the path.

## Persistence limits

- Single `.kaicut` JSON file, at most 10 MiB; references stay external.
- Schema version 2; at most 2 video + 2 audio tracks, 10000 clips and 24 hours. Positive clip duration, nonnegative safe integers, matching media/track types, valid source bounds and no overlaps within a track. Audio track volume is finite in 0..1; clip fade-in/fade-out are nonnegative and their sum does not exceed clip duration. Identifiers are unique within their media/track/clip namespaces.
- Splitting keeps only the original outer fades: fade-in on the left and fade-out on the right, clamped to each child duration; internal cut edges have zero fade. Cutting within a fade re-anchors it, rather than preserving an arbitrary envelope. Trimming preserves fade durations when they fit; otherwise it shrinks both proportionally using integer project frames (floor for fade-in, remainder for fade-out). Extending does not automatically lengthen fades. These edits remain one history step and round-trip through v2 without new fields.
- Runtime convention: `video-1` is always the primary video track used as the magnet reference. It is fixed by the application, is not configurable, and adds no persisted schema field. Magnet snapping is a frontend pointer-time convenience (Alt disables it); Rust receives the resulting explicit start frame and only validates locks, types, bounds and overlap. `rippleDelete` closes gaps independently per track and does not silently ripple other tracks.
- Accept valid schema-v1 empty timelines and recovery snapshots, migrating in memory to v2. Reject nonempty v1 clips rather than invent missing source offsets. Explicit save writes v2; earlier releases reject v2.
- Reject unsupported versions, unknown fields, duplicate IDs within a namespace, invalid bounds/references and oversized projects. New/open/recovery clear history and increment revision even for the same projectId. Save retains history. Failed edits leave session/history/revision unchanged.
- Relinking currently used media re-probes its source duration, rejects a source too short for existing clips, refreshes source bounds and clears obsolete timeline history. Changing unreferenced media does not alter clips. Audio mute and gain affect playback; hidden video tracks are omitted by preview and export.
- Save via a temporary file in the destination directory, flush/sync, then replace the destination; failed writes leave the prior file and session intact.
- Import preserves selected files and reads metadata only. Duplicate paths are skipped.
- Media link status, ffprobe metadata, and preview failures are runtime state; they are never written into `.kaicut`.
- Thumbnails are runtime-only PNG data URLs (at most 960 pixels on the longest edge and 4 MiB before base64). Decode uses a fixed file-only format allowlist, no shell, a 10-second deadline, single decoder/filter/encoder threads and capped process output. RGBA preserves image transparency and FFmpeg applies source rotation metadata.
- Thumbnail cache resides only in the application cache `thumbnails/` directory. SHA-256 keys include canonical source path, file size, full modification time and conversion version. Validate source size/time against the imported reference before and after cache/decode access; changed or missing references return no image. Temporary files are atomically renamed; generated PNGs are pruned oldest first before adding entries, within 128 MiB and 512 files. The command exposes no filesystem asset scope and does not change dirty state.
- Recovery snapshots are separate atomic JSON envelopes in the app-local data directory and are removed after an explicit successful save or discard.
- Export snapshots are separate immutable JSON files under app-local `export-jobs/<jobId>/snapshot.json`. The v2 project, output path, revision and used-media size/time fingerprints are captured without UI state or media bytes. Workers compare the on-disk snapshot to trusted in-memory data and recheck sources before and after encoding. Queued/failed/cancelled jobs may start only in the same app session. Restart loads bounded job.json history, marks unfinished jobs interrupted and removes only recorded job-owned temporary files after strict path checks; no automatic resume.
- Failed/cancelled workers explicitly verify temporary-output cleanup. If Windows file sharing prevents deletion, the tracked path remains in job.json and the job's error carries a cleanup warning. Retry must clear the old tracked temporary file first; startup recovery retains tracking while cleanup still fails. Successful publication never deletes the final output. `retryAvailable` describes current-process trusted-snapshot availability, not state eligibility: it must be combined with queued/failed/cancelled state before offering a start/retry.

## Current Windows export renderer

- 1920×1080 H.264 via h264_mf, 8 Mb/s; AAC 192 kb/s, stereo 48 kHz; project rational frame rate. No libx264 fallback. Actual MFT failure is reported by the worker.
- First unmuted video track in project order is opaque and takes precedence. Gaps are black/silent; images are flattened onto black. Embedded audio follows visible video intervals; unmuted audio tracks are mixed at their volume with linear fades matching frame-boundary gains. Summation is not normalized and can clip; there is no limiter/HDR/alpha compositing.
- Source pictures are fitted using display aspect ratio (including sample aspect ratio), then converted to square pixels before black padding. Raw coded width/height alone must not determine the export's visible proportions.
- 64 project clips / 64 rendered decoder inputs, conservative 24k UTF-16 command budget; excessive input expansion/path length fails explicitly. Frame/source offsets remain in project timebase. Probe budget 60s with individual 10s timeouts; cancel checked between probes, encoder cancel checked every 80ms. Encoding bounded at 24 hours.
- Media paths passed as Command arguments with file-only inputs; filter script contains only generated labels/numbers. stderr capped at 64 KiB; progress parser has bounded lines. Windows Job Object terminates encoder on app death.
- Owned temporary MP4 is created beside the destination; ffprobe validates H264/AAC, dimensions, frame count/rates and duration before fsync and persist_noclobber. Neither failure nor cancellation replaces an existing file. No background continuation after app exit.

## Preview projection and local MCP (2026-10-16)

- Runtime-only `previewMode` is `source` or `timeline`. Selecting library media uses source mode; selecting clips or seeking uses timeline mode. Source playback never advances the timeline. Mode/playhead/selection do not enter `.kaicut` or edit history.
- Timeline resolution ignores the selected clip. First non-muted video lane containing the half-open current frame wins, including an unavailable upper source (report it rather than showing a hidden lower lane). Only that visual's embedded audio and active independent audio lanes are mounted. Images are flattened against black, empty visual intervals remain black, and playback continues to the complete project duration including audio/image tails.
- Timeline playback takes presentation time from the first active non-muted independent audio lane, then the visible video when no independent audio is active. Zero-gain but non-muted audio remains eligible. A missing/waiting/seeking/unready master freezes project advancement and holds slaves; a monotonic WebView clock is used only for genuine media-free intervals. External seek explicitly rebases source positions. `preview-clock.ts` holds source-to-project mapping, consecutive-source detection and synchronization policy. The audio master stays at 1x; slaves use bounded 0.97–1.03 rate correction beyond 20ms, with hard seek for explicit jumps or drift over 250ms when no seek is pending. Same-source consecutive clips reuse their element; discontinuous mappings reposition it. Every mode/project/revision switch stops old streams and pause resets rates to 1. These are HTML media presentation clocks, not WASAPI/device-output positions; sample-accurate audio, frame-perfect decoding and gapless buffering on every device remain unproven.
- `--mcp` enables an authenticated raw NDJSON TCP bridge on 127.0.0.1 with random port/token. The stdio MCP SDK adapter in `mcp/server.mjs` reads app-local `mcp/connection.json`. Normal launches have no listener. Tokens are runtime credentials and never tool results. Protocol request/response limits are 1 MiB/16 MiB, four concurrent clients, UI acknowledgment deadline three seconds. See docs/MCP.md for tools and client setup.
- The current MCP allowlist has 20 tools. `get_state`, media and export inspection reuse native commands. `timeline_edit/undo/redo` reuse the same revision-checked Rust implementation and publish `kaicut:mcp-session` to the main page; stale revisions cannot restore an older project projection. Project file and export tools below are bridge-only typed commands, not generic filesystem access. Arbitrary script execution, project/output overwrite, client-supplied snapshots and custom FFmpeg arguments are not exposed.
- `ui_inspect`, `ui_seek/play/pause/select` use `kaicut:mcp-command` with requestId/action/args; the page rechecks current project/revision and modal/busy state before control. Main-window-only `mcp_ui_ack {requestId,result}` resolves a pending request once, with a bounded JSON object or error. UI inspection returns runtime state, media-element status, visible controls/bounds/computed styles and alerts, not screenshots. `imageNodes` contains at most two preview images with `complete`, `naturalWidth` and `naturalHeight`; complete alone does not prove a successful load, so require positive natural dimensions. `viewport` contains width/height plus document `visibility` and `hidden`; a hidden test window must not be described as a visually inspected visible window.
- Every successful `ui_*` response also receives Rust-read `nativeWindow: { visible, focused, minimized }` from the actual `main` WebviewWindow. These fields are independent of `viewport.visibility/hidden`, which describe the WebView document and can report visible while the native window is hidden. Do not infer native visibility from DOM state, launch flags, or a process MainWindowHandle without identifying the actual window; Tao may create a technically visible but transparent zero-sized event-target helper window.
- UI inspection samples additional runtime-only diagnostics without adding tools, background listeners or a global FPS loop. Each `mediaNodes` entry has nullable `expectedSourceTime`, `driftSeconds`, `totalVideoFrames` and `droppedVideoFrames`. In timeline mode, the matched clip determines expected seconds as `(sourceInFrame + playheadFrame - startFrame) * fpsDenominator / fpsNumerator`; source mode, an unknown clip or non-finite calculations return null. Drift is signed `currentTime - expectedSourceTime`, not measured hardware audio latency or proof of A/V synchronization. Non-finite currentTime is also null. Video counters come from optional `getVideoPlaybackQuality()` and are null for audio, unsupported/throwing APIs or invalid values; resource/element replacement may reset them. Do not merge different clip identities or interpret unavailable counters as zero or hidden-window counters as visible presentation FPS.
- The inspection response `performance` contains nullable finite `inspectedAtMonotonicMs` and `inspectionDurationMs`, plus integer `domNodeCount` and `timelineClipElementCount`. Start time uses the WebView's own performance.now clock, not the MCP client's clock. Duration covers synchronous page-side inspection only, excluding JSON response serialization, native/transport waiting and client processing; client round-trip measurements must remain separate. DOM count means all current elements, excluding text/comment nodes; timeline count uses the actual `.timeline-clip` selector and means mounted elements, not total project clips or verified visible pixels. Consumers must reject unavailable/non-finite samples before statistical aggregation; null must not become a false zero-drift success. These diagnostics do not enter `.kaicut`, undo history or dirty state.
- Clock diagnostics add nullable `preview.clockMode` (`audio`, `video`, `monotonic`, `source`), `masterKind`, `masterClipId` and `buffering`. Media entries add actual `playbackRate`, an element-lifetime `nodeId`, and cumulative `hardSeekCount`; missing attributes remain null. Continuous cuts should keep node identity and avoid extra seeks, while discontinuous source mappings require repositioning. `mcp:playback-check` uses these fields for a real 600-second run (or explicitly labelled `--seconds 30` smoke), followed by pause/seek and 14-second boundary cases. Reports retain all samples, startup and boundary diagnostics separately; relative audio/video project positions must be checked independently of the audio-derived playhead. Never present the diagnostic counters as physical sound/display synchronization.
- A 250ms no-progress watchdog also holds slaves when a ready, unpaused master stops advancing without a waiting event. Progress, explicit seek, a new master/clip, playback restart or a media-free gap reset its observation; 100ms-quantized clocks are tolerated. While held, slaves do not repeatedly hard-seek back to the stopped master.
- Timeline start and discontinuous seeks use one preparation gate: all active media must have metadata, a settled seek and readyState >=3 before the coordinator releases the master. Followers are released from their original prepared source positions only after the current-generation master play promise succeeds and its presentation time advances. Child readiness events may wake the coordinator but cannot independently start timeline media; source preview remains direct. A new seek/pause/revision invalidates earlier release authority; preparation/start has a bounded ten-second timeout. `preview.phase` exposes preparing/starting/playing/buffering/paused/source, or null when unavailable. This improves lifecycle ordering but current WebView startup quality still does not meet the one-frame target across repeated starts; see docs/PLAYBACK-STARTUP-VALIDATION.md.
- `--mcp-hidden` configures initial visibility false and focus false for background checks, disabling creation-time native/WebView focus requests. Debug-only `--mcp-validation` uses a separate process-specific app-data identifier; it never accesses the user's normal recovery metadata. It still requires --mcp. The normal client configuration uses the standard app-data path, not this test profile.

Starting probes concurrently would advance the shared generation and discard the new link results.

Its output root must stay inside this checkout's `src-tauri/target` after symlink resolution; each run uses a new UUID directory containing saved projects and `validation.json`. It requires a clean, unsaved empty session and verifies source hashes, sizes and modification times. The first inspection and every subsequent `ui_*` response must report `nativeWindow.visible=false`; the script fails otherwise instead of hiding or repairing the window itself. Reports retain both native and DOM visibility state. This workflow checks decoder/runtime state rather than screenshots or pixel equivalence; current execution results belong in docs/MCP.md only after the run actually completes.

Export request schemas reject unknown fields and require nonnegative JavaScript-safe integer revision values; job identifiers use the existing native job-ID validator. Failed preparation can have progressed beyond the client response deadline.

`pnpm mcp:export-check --connection-file <isolated connection> --output-dir <directory inside src-tauri/target>` is the `mcp:workflow-check --export` entry point. It first performs the complete generated-media import/edit/preview/save/reopen workflow, then checks preflight read-only behavior, frozen-snapshot independence from later edits, completed H.264/AAC metadata and decoded RGB/PCM, a destination created after preparation, queued/running cancellation, and task-owned temporary files. Only generated fixture copies and an isolated hidden/non-focusing validation instance are used; no desktop input automation. Its checks are acceptance criteria, not a claim that every run passes.
