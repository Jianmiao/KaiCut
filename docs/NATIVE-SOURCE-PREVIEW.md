# 原生素材预览接入

本轮将原生解码、独立 WASAPI 音频时钟和 D3D11 预览接到素材选择与播放控件。它是 Windows 开发开关下的源素材预览入口；普通启动与时间线预览仍保留原来的 WebView 播放路径。

## 启用与准入

编译时使用 `native-preview-host`，启动时同时传入 `--native-preview-host --native-source-preview`。开关关闭时不分配这一入口的设备或原生子表面。

首批只接受 Rust 当前项目中已导入且身份匹配的本地 MP4/MOV：视频不超过 1920×1080、明确为方形像素、无旋转或显示矩阵，音频为 48 kHz 双声道 AAC。只接收一条视频和一条音频流；无音轨、PCM、其他采样率、变换信息、超过 60 秒或 512 MiB 的素材返回不支持，由前端使用兼容预览。限制属于本次开发范围，不是 `.kaicut` 文件格式限制。

前端仅提交项目 ID、项目 revision、媒体 ID 和请求 ID；Rust 从权威项目会话取得路径。探测和播放均使用固定 SHA-256 校验的 LGPL sidecar，禁止 PATH 查找、shell 和网络协议。源预览的流式解码器允许审计 checkout 路径，或当前应用可执行文件同目录、其 `binaries/` 子目录内的固定 `ffmpeg.exe` / `ffprobe.exe`；路径规范化后仍须匹配相同的审计 SHA。旧独立诊断入口保留严格 checkout 路径。该准入不接受任意路径上的同名文件，也不等于安装包验收已经完成。

准备时先检查元数据，再分别读取真实视频帧 PTS 与音频 `nb_samples`。每个 FFprobe 子进程最多 10 秒，输出上限 8 MiB，每条流最多 100,000 个帧记录，单次 FFmpeg 分配上限 32 MiB。完整准备包括文件哈希和最多三次探测，因此“10 秒”不是所有准备工作的总耗时保证。所有探测、等待和解码都在后台线程进行。

## 时间与文件身份

归一化时间零点来自第一张实际解码视频帧；音频使用第一块实际解码 PCM 对应的原始 PTS。不能再次扣除已由解码器处理的 AAC priming。音频 PTS 必须按真实样本数连续；发现间断、重叠或不对齐就退回兼容路径。

音频长度由解码帧的样本数相加得到，不把码率或容器时长当成 PCM 数量。视频片尾使用最后一帧的 PTS 加帧时长；缺失帧时长时才使用流的结束时间。最终可定位范围取归一化音频与视频末尾的较大值，并限制在 60 秒以内。

准备期间源文件以只读共享方式持有，防止写入与删除；比较前后大小、精确修改时间和 SHA-256。播放开始前再次比对准备时的身份，并持有同样的文件句柄直到音频和解码线程结束。用户媒体和项目 JSON 均不被写入。路径准入拒绝 UNC 和设备前缀；映射到网络位置的盘符仍需后续单独验证。

## 控制与所有权

素材选择创建独立 token。播放、暂停、定位、状态查询及关闭都检查该 token；旧 token 的清理不得关闭较新素材。项目 revision 或媒体引用改变会使旧会话失效。前端对状态和播放请求串行处理，合并等待中的定位意图，并丢弃过时的打开响应。

定位参数为十进制整数纳秒字符串，接受 `[0, duration]`，包含精确片尾。源播放器在片尾保持最后一帧；进入结束状态前必须观察到真实视频 EOF、最终帧提交和音频缓冲耗尽。结束后播放从零开始。界面时间不超过源时长。

原生画面只占既有预览画布，播放和定位控件仍为 DOM。布局变化或弹层覆盖沿用原生表面的隐藏、恢复与裁切规则。无法可靠关闭原生会话时，前端显示错误而不同时启动第二个 WebView 解码器。

## 验收状态

纯测试覆盖原始时间偏移、负音频起点、VFR、最后帧时长缺省、音频间断、格式拒绝、整数时间边界及文件身份。

首批隐藏测试发现准备阶段找到打包目录内的同 SHA sidecar，而解码器仍只接受 checkout 路径，导致支持范围内的素材退回 WebView。失败证据保留在 `src-tauri/target/native-source-validation/batch-1a174b4f-85b6-470b-ae83-2a2e85d359b7`；不能将这批记录算作原生播放通过。

随后 `batch-d2041ce7-f3d2-44e8-9dab-43ca46bfbd6d` 已实际播放并暂停，但隐藏窗口没有实际焦点，验证者使用 `focus()/blur()` 未触发定位输入的 React 提交事件，停在暂停状态并超时。验证者现改用明确的 DOM `focusin`、输入/更改、`focusout` 事件及渲染间隔；这仍是 DOM 控件测试，不是物理键鼠输入测试。

`batch-7b0232b1-f336-42a8-a70b-a6b5599fce40` 的流程走到兼容回退，但子表面先释放后，主进程退出打断了后台报告落盘，只留下临时文件。这一批也不能作为完整通过证据。报告持久化已移到主线程退出清理中的同步路径；重新验收须同时检查最终 JSON、清理结果和进程退出。

修正后的 `batch-30fe9ed9-bab6-404c-8f6e-8193639d38e5` 已完成两轮真实隐藏应用验收。独立脚本 `target/native-source-validation/verify-source.cjs` 复核通过两份报告：共九个控件状态步骤，包含播放超过 2 秒、暂停、接近片尾定位、自然结束、重播、精确片尾、切换同内容素材、旧 token 关闭保护和无音轨素材的 WebView 回退。两轮均独立重算 320×180、90 个视频帧、188 个音频帧、192512 个采样、音视频实际起点和 `4,010,666,666 ns` 归一化长度；观察到零音频断供，sidecar 子进程全部实际退出，原生子表面与 DirectComposition 解绑清理通过。

验证报告：`target/native-source-validation/batch-30fe9ed9-bab6-404c-8f6e-8193639d38e5/source-verification-03dcdda2-54f2-4320-ba8c-77e866f603c5.json`。该证据只证明隐藏窗口中的原生 API、Rust 权属、DOM 控件状态和后台资源清理；它不能证明可见窗口的像素外观、扬声器输出、屏幕刷新率或物理音画同步。隐藏验证仅静音自身的独立音频会话，不改变系统音量或默认设备。

## 后续范围

基础控件与顺序关闭已通过上述两轮隐藏实例。后续六个独立实例已验证真实重叠的A→B→A选择、actor创建前的准备中退出、播放中正常退出，并修复打开登记与退出封门的竞态；见 [NATIVE-SOURCE-STABILITY.md](./NATIVE-SOURCE-STABILITY.md)。这仍是短素材、有限切换次数的验收，不覆盖每个准备子阶段或无限压力。当前上传的是RGB8，未证明HDR或完整色彩管理；更广素材、原生多轨/混音、安装包、高分辨率长时负载、可见窗口性能和物理同步仍需分别验收。
