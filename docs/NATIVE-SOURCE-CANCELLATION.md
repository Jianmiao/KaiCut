# 原生源预览取消与关闭保护

范围是Windows显式开发开关下的源素材播放器；默认WebView与时间线、项目格式和导出不变。验证只使用隐藏实例、生成素材与隔离应用数据目录，不操作桌面，不更改系统音量或设备。

## 取消准备

每次打开保留独立requestId。界面离开尚未准备完成的素材时，使用该请求的项目上下文和requestId取消准备，而不是等待一个尚未返回的播放token。取消只标记匹配请求，不让旧请求改变较新会话。登记、历史、取消审计和处理乱序的记录都有容量限制；重复/超额登记不能使已有请求过期。

源文件和sidecar哈希每64KiB检查取消，元数据/音频/视频探测在阶段边界与运行中轮询检查。取消通过进程对象持有的私有句柄终止探测，并回收进程、等待stdout/stderr线程结束后才完成打开请求。未完成或无法确认的清理会进入关闭保护，不能作为一般“不支持素材”直接启动兼容播放器。

取消回复只确认意图。前端仍等待原打开请求完成，并关闭它可能迟到返回的token；取消通信或关闭失败保留错误状态，不能同时挂载HTML播放器。旧请求的迟到响应只回收自己的token。

## 关闭保护的实例验证

测试在真实actor、解码器和原生绑定已经收尾之后，单次注入“清理确认失败”的返回值。预期原生运行时保留失败token，重复关闭仍失败；尝试打开B仍返回该失败身份，界面保持错误态且无HTML媒体节点，没有第二个actor。这验证保护分支，不代表真实COM解绑、WASAPI Stop/Reset失败已经被复现；实际资源会照常释放，不故意遗留设备或窗口。

## 验收准则

| 场景 | 必须观察的事实 |
| --- | --- |
| 探测中回时间线 | 点击真实模式按钮触发请求取消；同一请求至少有一个探测在取消观察点仍活着，随后非零退出且两个读取线程完整结束；时间线空态无播放器，之后B可正常原生播放。 |
| 探测中切B | A和B身份独立；A真实在途探测被取消，B不受旧请求取消/迟到响应影响，从零准备和播放。 |
| 清理确认失败 | 先真实播放/暂停A，再实际解绑后注入失败；A和B均显示错误、播放按钮禁用，没有HTML或原生第二播放器；失败身份持续保留，正常退出仍完成已拥有资源的回收。 |

探测可能在UI消息往返期间跨阶段，因此验收要求同一请求内存在真实运行中的探测被中断，而不是强求最初采样到的阶段一定被中断。自然退出的探测也必须完整回收；取消标记不能把自然退出变成强制中断证据。

## 限制

5ms是后台检查间隔，不是用户请求到关闭的硬实时上限；文件系统读取、管道、系统调度、设备初始化及驱动调用仍可能延迟。本批细粒度取消覆盖profile探测/哈希；设备打开后与actor首次准备循环中的检查和受控验收已在后续批次完成，见 [设备与首帧准备取消](./NATIVE-SOURCE-STAGE-CANCELLATION.md)。可见输出、听感、真实设备故障与物理音画同步继续独立验收。

## 实际结果

六个独立隐藏实例通过，三场景各两轮。正式批次为`src-tauri/target/native-source-validation/shutdown-224791b0-9b04-4da7-a3e9-d91817fbc4dc`；独立报告`shutdown-verification-feeaa456-a9ee-4ee7-a768-62c3dea5bb59.json`为`ok=true / complete=true`。

| 场景 | 主进程PID | 结果 |
| --- | --- | --- |
| 探测中回时间线 | 35616、41060 | 对应元数据探测38532、19876在取消观察点仍活着，随后退出码1；两个读取线程join、进程reap和请求退役全部确认，空时间线无播放器，B恢复原生播放。 |
| 探测中切B | 46204、30428 | 对应探测4652、8332实际中断，A结束后没有创建actor；B从零准备并播放超过300ms，旧请求未关闭B。 |
| 清理确认失败 | 5136、38528 | A真实播放/暂停后完整关闭并解绑，再注入一次确认错误；旧token始终拒绝关闭确认，尝试B仍返回同失败token。两个错误占位均无HTML媒体节点、无active原生actor且播放禁用。 |

四个被取消探测的总存活/清理计时分别约18.91、17.65、19.12、22.02ms；这包含探测启动到结束，不是从用户输入到取消完成的延迟指标。验收同时要求取消观察点进程尚未退出、最终非零退出码、相同PID、reader/stderr已join、cleanupErrors为空，不能用自然退出替代中断证明。

独立校验从原始证据确认6个主进程、18个解码子进程及22个探测子进程均退出，64项源码/程序/前端产物/sidecar身份一致，并拒绝84个内存负例；没有改写原始报告。首个独立校验因错误假定打开命令trace含projectId/revision而拒绝数据，失败报告保留；现按真实requestId/mediaId配对，并由runtime准备记录和取消命令完整上下文核对。

同一程序完成基础9步骤回归（主进程5696，退出0），包含播放/暂停/定位/EOF/重播/切源/兼容回退。证据位于`target/native-source-validation/shutdown-controls-2472730f-4323-44fb-8bc1-c349d68b5b81/source-verification-dc6b9ad6-ba1e-4a84-b3ea-6a48b9655dc2.json`（相对`src-tauri/`）。

工程检查：前端292项通过，Rust默认102项通过/6项忽略，原生feature338项通过/8项忽略；lint、前端构建、Rust格式和内嵌前端的原生构建通过。忽略项不计通过。默认构建不启用原生播放器，验证构建继续使用`native-preview-host,tauri/custom-protocol`。
