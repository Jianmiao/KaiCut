# KaiCut 产品规划与 MVP PRD

- **状态**：规划稿 v0.1
- **范围**：本地优先桌面视频剪辑工具，Windows 当前首发；macOS 有设备后再适配验收；Linux 延后
- **关联设计**：[DESIGN.md](./DESIGN.md)、[DESIGN-TOKENS.md](./DESIGN-TOKENS.md)
- **实现约束**：本文件只定义产品范围与验收要求，不创建应用源码

## 一句话定位

KaiCut 是一款面向个人创作者和小型内容团队的本地优先桌面视频剪辑工具，先在 Windows 上提供清晰、低干扰、可恢复的基础多轨剪辑体验。macOS 待获得设备后再单独适配与验收。

## Slogan

**让剪辑回到画面本身。**

## 产品原则

1. **本地优先**：项目和原始媒体默认保留在用户设备上，离线时仍能完成核心剪辑。
2. **可恢复**：保存失败、异常退出、媒体移动和导出失败都必须有明确状态与恢复入口。
3. **时间准确**：内部使用整数或有理数时间基，禁止用 JavaScript 浮点数累计剪辑位置。
4. **内容优先**：预览、时间线和波形使用稳定实色；毛玻璃只服务于工具栏、菜单和短小弹出层。
5. **平台诚实**：当前只以 Windows 实机结果交付；采用其窗口、菜单、文件选择器、快捷键与权限规则。Apple 风格是视觉参考；未来 macOS 支持须独立验证。
6. **渐进增强**：先验证软件解码和实色降级，再启用硬件路径。LGPL FFmpeg 下编码能力单独探测；软件解码不代表具备软件 H.264 编码能力。

## 目标用户与任务

### 首要用户

- 需要快速剪出短视频、教程、演示和社交媒体内容的个人创作者。
- 需要在本地管理素材、反复修改并输出常见格式的小型内容团队。

### 首要任务

1. 创建或打开项目。
2. 导入视频、音频和图片，确认媒体状态。
3. 在时间线中完成选择、移动、裁切、分割、删除、吸附和撤销。
4. 预览并检查音视频同步。
5. 保存、恢复媒体链接并导出成片。

## MVP 范围

### P0：必须具备的首发能力

| 领域 | P0 范围 | 明确验收 |
| --- | --- | --- |
| 项目 | 新建、打开、最近项目、保存、自动保存、异常退出恢复 | 强退后能恢复最近一次有效编辑；保存失败有原因和重试 |
| 媒体 | 导入常见视频、音频、图片；异步读取元数据、缩略图和基础波形 | 导入期间界面可继续操作；损坏或不支持格式有明确错误 |
| 时间线 | 2 个视频轨道 + 2 个音频轨道；添加、移动、裁切、分割、删除、吸附、锁定、静音 | 关键编辑可以用鼠标和键盘完成；撤销/重做可靠 |
| 预览 | 播放、暂停、逐帧、拖动定位、时间码输入、音频监听 | 常见 CFR 与基础 VFR 素材可定位；播放时没有持续音画漂移 |
| 媒体链接 | 离线状态、重新链接、路径错误说明 | 移动原始文件后可通过重新链接恢复项目 |
| 导出 | H.264/AAC MP4、一个 1080p 默认预设、进度、取消、失败重试 | 导出使用提交时快照；后续编辑不改变正在运行的任务 |
| 可访问性 | 键盘闭环、焦点可见、弹层焦点管理、基础语义时间线、减少动态效果和透明度开关 | 仅键盘可完成核心流程；当前 Windows NVDA 能读出主要状态，VoiceOver 延后 |
| 平台 | Windows 首发；macOS 与 Linux 暂不纳入当前交付 | Windows 可安装、打开项目、编辑、导出；以各阶段实际完成项验收 |

P0 不承诺 HDR、专业调色、复杂特效、插件、云协作、多人协作、转录、多机位、后台持续导出或 Linux 正式支持。

### P0 媒体支持矩阵

P0 先承诺一组可测试的常见媒体，而不是声称“支持所有视频”：

| 类型 | P0 目标 | 处理边界 |
| --- | --- | --- |
| 容器 | MP4、MOV；对常见 MKV 做探测并明确标记 | 容器可打开不代表其中所有编码都可编辑 |
| 视频 | H.264 8-bit 4:2:0；常见帧率 24、25、29.97、30、50、60 | HEVC、10-bit、HDR 和特殊色彩范围先走能力探针或清晰降级 |
| 音频 | AAC、WAV/PCM、MP3；44.1kHz 和 48kHz | 多声道先按可监听与导出矩阵验证，不默认承诺专业混音 |
| 图片 | PNG、JPEG | 旋转和像素尺寸 metadata 必须保留或明确提示 |
| 时间 | CFR 首发；VFR 必须被识别并正确显示 | 不支持或异常素材不能静默当作 CFR |

不在矩阵内的格式需要显示“无法读取 / 需要代理 / 仅可导出”的具体原因和下一步。该表是测试范围，不是编解码器授权结论。

### P1：验证核心工作流后加入

- 代理媒体生成、代理切换和代理失败恢复。
- 更多导出预设、导出队列和批量导出。
- 更多轨道和轨道组管理。
- 音频增益、淡入淡出、速度调整、关键帧。
- 基础转场、字幕/文本图层和标记点。
- 更高精度的多尺度波形、缩略图缓存和时间线性能优化。
- Windows Media Foundation/D3D/WASAPI 的稳定硬件路径；macOS VideoToolbox/Metal/CoreAudio 列入获得设备后的独立适配计划。
- 项目包内复制媒体的可选工作流和更强的媒体搜索。

### P2：长期能力

- GPU 特效、蒙版、抠像、专业调色、HDR 和色彩管理。
- 语音转录、字幕自动生成、模板和素材库。
- 多机位、复杂嵌套序列和高阶音频混音。
- 云同步、协作、评论和团队权限。
- 插件 SDK、脚本自动化和扩展市场。
- Linux 正式支持和更多桌面环境适配。

## 首发成功标准

这些是产品验收目标，不是已有用户数据：

- 新用户可以在不阅读长文档的情况下完成“新建 → 导入 → 基础剪辑 → 导出”。
- 代表性 10 分钟项目在播放和连续编辑时，音视频漂移小于 1 帧；定位误差不超过 1 帧或 1ms，以较严格者为准。
- 1000 个片段的测试时间线可以完成选择、滚动、缩放和撤销，不因 React 逐帧重绘而失去可操作性。
- 导出失败、磁盘不足、媒体离线和异常退出都不会静默丢失最近一次有效项目状态。
- Windows 在 P0 流程上通过安装、升级、卸载和干净机器测试；macOS 验收延期，不作为当前发布门槛。

## 明确不做的产品承诺

- 不宣称浏览器 WebView 可以完全复现 AppKit 或 Windows 原生渲染。
- 不宣称所有格式、编码器、HDR 和色彩管理都可用。
- 不把 FFmpeg 的开源许可证等同于所有编解码器或专利风险已经解决。
- 不把硬件加速当作所有机器的必有能力；解码按已验证的软件路径降级，编码按实际可用 LGPL 编码器决定。H.264 编码器不可用时提示，不隐式启用 GPL 编码器或改变输出格式。
- 不在没有冲突提示的情况下覆盖被其他应用修改的项目，也不静默覆盖已存在的导出文件；默认采用版本化文件名或明确确认。
