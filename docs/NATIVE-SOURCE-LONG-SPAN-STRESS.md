# 原生源预览 59 秒跨度压力验证

## 范围与素材

2026-10-18，在 Windows 的显式 `native-preview-host` / `native-source-preview` 开发开关下完成固定两轮验证。实例使用 `--mcp --mcp-hidden --mcp-validation`，保持隐藏、不获取焦点，只静音自身 WASAPI 会话；没有桌面输入、可见画面或真实听感验收。默认播放器仍为 WebView。

本批将上一批 20 秒跨度样本扩展至 59 秒，并保持现有 60 秒准入上限。生成素材为 320×180、30fps、H.264，加 48kHz 双声道 AAC；没有扩大分辨率、格式或设备资格。

独立 ffprobe 原始帧记录确认 1,770 个视频帧、2,766 个 AAC 帧和 2,832,384 个音频采样。视频端点为 59,000,000,000ns，AAC 补齐后的音频端点为 **59,008,000,000ns**，会话使用两者最大值。不能直接把容器的 59 秒当作精确音频结束时间。夹具清单为 `src-tauri/target/native-source-validation/long-span-fixtures-59s-20261018-r3/fixture-manifest-v2.json`，SHA-256：`23da8354133442a5ee1d13443386f5bd72a782d01eb8f53363a3ab380b0a999e`。

## 固定步骤与证据要求

每轮记录 14 个步骤：选择素材并等待 Ready；播放至会话中点（29.504 秒）后暂停；保持暂停至少 150ms；恢复并自然播放至 EOF；定位到 7.5 秒、播放至少 1 秒后暂停；定位到 30 秒、播放至少 1 秒后暂停；定位至片尾前 200ms 并播放到 EOF。

首段包含两次 Start，均为 source epoch 1；三个定位段依次为 epoch 2、3、4。恢复后的前进量以实际暂停位置为基准，至少前进 300ms。暂停观察仅比较缓存位置和 pump count，不读取新鲜设备时钟。生命周期与 Start/欠载账本必须完整；128 项视频事件是滚动记录，不能声称覆盖全部 1,770 帧。

不注入延迟，不改变音频缓冲或播放参数，不因欠载而提前停止或追加次数直到通过。独立校验把证据完整性与自然欠载计数分开，并从原始帧记录重新计算端点、定位采样边界和账本关系。

## 启动确认修订与保留记录

`long-stress-r4` 第一轮应用报告完整；第二轮在初始 Ready 前超时，0 步、0 次 native source 命令。该轮不是欠载观察，不能计作零欠载。旧验证在发布导入会话后只等待固定 750ms，没有确认实际素材卡片已经出现。本轮将它改为在有界等待内重新发布已提交的同一会话，并确认实际 DOM 包含全部预期素材卡片，再继续选择；不会重复导入文件。新测试覆盖缺失或不完整卡片不得放行。r4 没有保留失败当时的 DOM，不能据此断言事件丢失是唯一根因。

`long-stress-r5` 两轮及当时的独立核验通过，但后续构建替换了可执行文件，重新核验正确地因程序哈希变化而拒绝旧批次。因此 r6 在最后一次构建后重新执行完整两轮；不混用 r4、r5 或早期探索结果。所有原报告和失败核验记录保留。

## 复现与后续

先完成构建，再创建新的空批次和 `span-1`、`span-2` 子目录。顺序调用 `run-long-source-check.ps1`，分别传入子目录的**绝对路径**、对应 RunLabel 和上述夹具绝对路径；随后运行 `node verify-long-span.cjs <批次目录>`。脚本拒绝覆盖证据，核验后不得重建程序再把旧结果声称为新二进制的验收。

这两轮只证明本机固定低分辨率、接近 60 秒样本的控制流程与账本完整，未复现自然欠载。历史自然欠载根因仍未确定，也未证明可见画面、听感、物理音画同步、分钟级以上素材、其他编码/设备、真实驱动故障或默认后端切换。下一步优先扩展代表性分辨率和素材矩阵，保留诊断；可见窗口及听感仍遵守桌面操作暂停的约束，另行验收。
