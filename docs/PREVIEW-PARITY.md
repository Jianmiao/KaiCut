# 时间线预览与导出规则一致性

日期：2026-10-16。原实现优先播放选中片段，容易与导出的轨道合成不同，并且空隙推进依赖相邻视频片段。现在素材预览和时间线预览明确分开。

- 素材模式播放选中源文件，不改变时间线播放头，不混入项目音轨。
- 时间线模式忽略选中片段，使用首条未隐藏的视频轨；遮挡结束后恢复下层，缺失上层显示错误而不悄悄露出下层。
- 视频空隙显示黑场，透明图片铺在黑色背景；图片和纯音频区间也可播放，持续到整条时间线末尾。
- 只有当前可见的视频原声与最多两条活跃音轨参与预览。音轨静音、音量和淡化使用当前项目值，源时间按项目有理数时间基计算。
- 暂停、模式切换、项目切换和编辑 revision 更新停止旧媒体节点；晚到的 play Promise 不会重新启动已暂停或卸载的节点。手动定位会重新锚定预览时钟。
- 只挂载当前需要的媒体节点，不为整条时间线创建成百上千个隐藏 audio 元素。时间线时间/总时长与素材时间分开显示。

`src/test/fixtures/preview-parity.json` 同时由 TypeScript 帧解析器和 Rust 导出测试读取，核对半开区间、图像优先级、源入点、静音和音频淡化增益。组件测试使用可控时钟及媒体 API 模拟验证实际事件/节点行为，不把模拟测试当成实际解码验收。

上述首批实现使用 WebView 的单调时钟和媒体元素，按帧更新增益并在漂移超过阈值时同步；这是 65 秒性能基线测得约 65–73ms 音视频时钟差的历史路径，并非原生音频主时钟。导出仍按既定 1080p H.264/AAC 规则离线生成。MCP `ui_inspect` 可观察真实节点 currentTime/paused/readyState，但这些不是截图或听感证据。

修改范围：`preview-area.tsx` 与测试、`timeline-preview.ts` 与测试、项目 store 的运行时预览模式、共享 fixture 及 Rust parity 测试；`.kaicut v2` 和原媒体文件不变。MCP 接入与真实进程验证见 [MCP.md](./MCP.md)。

## 已批准的下一批：音频主时钟

范围是时钟、同步策略和现有 WebView adapter；没有 UI 设计改动，不引入新的项目字段、编解码器或导出 renderer。计划见 [preview-clock plan](./superpowers/plans/2026-10-16-preview-clock.md)。600秒真实运行与边界检查已完成，具体通过范围和开播/切段限制见 [AUDIO-CLOCK-VALIDATION.md](./AUDIO-CLOCK-VALIDATION.md)；下列要求不表示全部产品质量门槛已通过。

| 情况 | 时钟与媒体行为 |
| --- | --- |
| 存在活动音频 | `resolved.audio[0]` 按项目轨序选主；静音轨排除，未静音的零增益片段保留。读该元素 currentTime，经源入点映射到项目时间；其它流跟随 |
| 无活动音频，存在可见视频 | 使用视频媒体时钟，保持相同源时间映射 |
| 只有图片或真实空隙 | 用单调时钟推进项目位置，直到下一媒体区间 |
| 预期主媒体缓冲/正在 seek | 缺失/错片段、waiting、readyState<3、seeking 或尚未播放时冻结项目时钟并暂停从节点；恢复后重锚 |
| 主媒体无 waiting 事件但停止前进 | 同一节点/片段 currentTime 连续 250ms 未前进则冻结并暂停从节点；允许 100ms 量化更新。显式 seek/换片段/暂停重置 watchdog；主媒体恢复前进后解除冻结 |
| 从节点小幅漂移 | 20ms 内保持 1x，20–250ms 通过 0.97–1.03 playbackRate 校正；暂停/回到容差时恢复 1x |
| 从节点偏差超过 250ms | 没有未完成 seek 时才硬定位；显式用户 seek/非连续源入点单独强制同步；元数据不足时保留请求等就绪事件 |
| 同源相邻片段 | 按稳定媒体/轨道身份复用节点，更新 clip ID 和源范围；源时间不连续时正确重定位 |
| 暂停/切项目/切模式/编辑 revision | 停止旧媒体与旧播放任务，重置时钟状态；晚到 Promise 无权重新启动旧流 |

`src/lib/preview-clock.ts` 通过 `mediaProjectFrame / continuousSource / syncAdjustment` 处理纯时钟映射和同步决策；预览协调器处理主时钟选择、冻结和衔接，WebView adapter 采集真实媒体状态与执行决策。它们都不修改 Rust 项目文档。未来原生音频位置、解码队列与纹理输出需要独立 probe，不将 WebView `currentTime` 命名成 WASAPI 时钟。

## 长时与边界验收要求

启动后续修订：所有活跃时间线节点先完成统一准备，主节点当前代play成功且实际时间前进后才放行从节点；媒体事件仅更新准备状态和唤醒协调器。请求撤销、10秒超时和source模式分别处理。首轮与重复启动必须独立检验，不能借连续稳定段门槛声称起步达标。当前功能已通过、重复启动质量仍失败，详见 [PLAYBACK-STARTUP-VALIDATION.md](./PLAYBACK-STARTUP-VALIDATION.md)。

- 在 Windows 的隔离、隐藏、无焦点真实 Tauri 实例中，经 MCP 运行至少 600 秒连续合成音视频播放；同时记录真实经过时间与媒体推进量，不能用 10 分钟素材只抽测开头几十秒。
- 独立比较音频和视频映射后的项目时间，记录 P50/P95/最大值、首尾偏差、漂移趋势、主时钟来源、缓冲次数/时间、硬 seek 次数与原因。项目时钟来自音频后“音频对项目误差接近零”是构造结果，不能代替音视频同步证据。
- 分开保留全部样本和稳定样本；明确开播、seek、切段/切主时钟排除窗口与覆盖率，不把边界异常静默排除。30fps 一帧约 33.33ms；稳定 P95 与最大值分别报告。任何未满足 M2 一帧目标的项保持开放。
- 验证开头、中段、尾部的正反向 seek，等待真实媒体完成定位再记录误差；分别记录请求往返与媒体稳定耗时。暂停后播放头与所有媒体时间稳定，恢复不追赶暂停期间的墙钟。
- 验证同源连续分割不卸载媒体节点、同源非连续入点正确定位、切换素材正确换节点、两音轨主从切换、视频空隙与图片区间、主媒体缓冲停止推进。seek 未完成时不重复提交；源文件指纹及项目内容不被观测修改。
- 边界夹具为 14 秒/420 帧：0–4 秒连续源分割，4–6 秒同节点的相邻源入点跳变，6–8 秒无媒体空隙，8–10 秒跳到新源位置，10–12 秒仅音频，12–14 秒仅视频。连续剪切不增加硬 seek；相邻不连续源复用节点但必须定位，不能用“节点没换”推断内容正确。
- 当前可确认的结果范围是 WebView 媒体时钟和运行时节点。可见窗口的呈现 60fps、实际声卡延迟、听感、设备兼容、VFR/HDR 或采样级混音需要单独验收；隐藏实例的数据不能关闭这些门槛。
