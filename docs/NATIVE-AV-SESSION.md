# Windows 原生音视频会话协同验证

本轮承接 [音频预览适配器](NATIVE-AUDIO-ADAPTER.md)，将同一流式解码器的视频帧与真实 WASAPI 设备时钟协调起来，再交给共用异步 D3D11 离屏渲染器。目标是验证 VFR 选帧、暂停恢复、双管线定位与取消的统一控制边界。

实现仍限于独立诊断程序，不接入主应用、UI、MCP 或项目格式。没有可见窗口、桌面控制、GPU Present 或录音；音频使用自有静音会话。结果只证明时钟选择、解码内容和离屏计算，不证明物理音画同步或屏幕显示流畅。

## 时钟、选帧与资源边界

音频主时钟使用 WASAPI 原始 position 及其 frequency，映射为当前项目锚点加设备已消费时间。设备频率不是默认采样率；PCM 已接受数量、解码预取位置和 padding 不能代替播放时钟。每次 Reset/seek 重建基线，暂停后时间保持，不能把旧设备位置带入新锚点。

音频与视频来自同一个 `StreamingDecoder` 所有者，内部仍分别拥有 RGB、PTS 和 PCM sidecar 管道，不等于单个操作系统进程。传输层保留当前帧和下一未来帧各至多一个，通过窄接口查询目标时刻已到期的真实 PTS 帧。VFR 不用平均帧率推编号，未来帧不提前渲染；单次查询最多读取 8 个已有帧并返回“已观察到的最后到期帧”，暂时缺帧时允许保留旧画面，不等于已证明没有更新的到期帧尚在解码。

准备阶段必须核对独立参考里的准确目标帧，不能只拿队列里最早可用帧当作准确目标画面。保留帧和解码队列分别有界，视频等待不得在播放线程阻塞音频供给。当前 AV 入口拒绝源音频已到 EOF 的初始/定位目标；纯视频及音频结束后仍继续视频的情况尚不纳入本轮。

渲染任务提交到独立 worker，运行期只非阻塞地取最新完成结果，不等待 GPU 读回。提交和消费时核对源代次与渲染代次，旧在途 GPU 工作可完成，但不得作为新会话的画面发布。报告区分选帧、提交、GPU 完成及消费，不把这些计数都称为显示帧数。

## 生命周期规则

首次准备需要音频端点预填和下一 PCM 包就绪，同时目标所属视频帧完成实际离屏渲染校验，之后才能显式 Start。设备停止的控制阶段可以等待 GPU；运行期不得因此卡住供音。

暂停先停止音频，再使渲染代次失效并回收旧任务；恢复前重新提交当前画面并确认完成，音频设备不 Reset。定位先停止并清空音频设备，同时清理当前/未来视频帧和旧渲染结果，再以新锚点、新代次重新准备。取消终止音频传输和 decoder，清空渲染队列，最终回收共用图形资源。任何错误仍需按所有权完成停止与清理，保留原始错误及清理记录。

## 受控验收

素材沿用 `fixtures-d924c584`：真实零起点 VFR 视频与非周期偏移 AAC。视频完整参考含 239 帧；音频首个解码帧位于 1.978 秒，完整 PCM 为 481,280 帧，不能根据封装命令改写为 2 秒。

依次从 2.2 秒播放约 0.6 秒并暂停 200ms，从 7.123 秒播放约 0.6 秒，再从 0 秒和 9.5 秒各播放约 0.4 秒，期间验证定位与取消。每段记录原始时钟、项目时间、真实帧 PTS/编号、源及渲染代次、RGB/RGBA 内容摘要、PCM 提交、padding 和资源回收。实际次数与结果以报告为准。

独立验证应从时基和参考帧表重新计算应选帧，并校验每个消费结果来自对应源、未提前使用未来帧；PCM 捕获仍只是已接受输入，可能有随后被定位清掉的队列数据。旧单音频成功结果不作为本轮音视频协同通过的证据。

## 实际协同运行结果

最终批次 `batch-789e83f7` 的 [第一次 AV 运行](../src-tauri/target/native-av-session-validation/batch-789e83f7-4021-43a8-97b0-948c5fd0b538/run-f749559b-5c96-4daf-9b1b-0d64449c3529/native-av-session-validation.json) 和 [第二次 AV 运行](../src-tauri/target/native-av-session-validation/batch-789e83f7-4021-43a8-97b0-948c5fd0b538/run-48cf09fe-4ca3-47c5-8ee1-eb5c97ed2171/native-av-session-validation.json) 均完成 4 段、3 次定位及取消。每轮设备接受音频帧依次为 30,816、30,816、21,216、21,216，合计 104,064 帧；仍包含之后被控制事件清掉的排队数据。

四个锚点准备完成的源视频帧分别为 50、160、0、214，均在音频 Start 之前完成 GPU 内容核验。每轮提交 49 个渲染任务，消费 45 个 GPU 完成结果，其中 40 个来自播放阶段、5 个来自准备阶段。不能将提交数等同于消费数或屏幕显示帧数：另有 3 个旧代次完成被拒绝、1 个已完成结果被控制事件清除；积压淘汰数为 0。

首次播放暂停时设备位置冻结在 84,480 / 384,000 秒，项目时间为 2.42 秒；音频源游标 22,272，待提交 384 帧源 PCM 保持。音频停止后渲染代次递增，再重新绘制参考帧 54，确认完成后才恢复音频。三次定位清空音频设备与旧视频状态，源代次依次为 1、2、3、4；最终取消后时钟和 padding 均为 0，禁止新工作。

两轮最大供音循环间隔分别为 10.3758ms、10.3964ms，低于实际 22ms 缓冲，AV 段均未观察到下溢。图形实例每轮共用到最后，最终关闭分别为 12.4639ms、12.7664ms；渲染队列无未完成任务，MMCSS 恢复及自有解码器回收记录完整。
