# 原生源预览生命周期稳定性

本批覆盖显式开发开关下的单源素材预览；普通启动、WebView时间线、项目格式与导出逻辑不变。基础播放/EOF证据见 [NATIVE-SOURCE-PREVIEW.md](./NATIVE-SOURCE-PREVIEW.md)。

## 问题与修正

原实现分别更新打开请求的代次和在途计数，退出路径又分别读取活动标记和计数，不能在一个原子步骤中决定“先登记打开”还是“先开始退出”。空闲退出返回时也没有封住新的打开请求。

`LifecycleGate`现在用短时间互斥锁统一登记、代次与退出状态。退出先封门：此前登记的请求计入等待，此后请求直接拒绝。请求guard在完成或放弃时退役；计数溢出拒绝登记，退出代次饱和后仍由退出标记失效所有请求。等待媒体线程、OWNER或Tauri事件线程时均不持门闩锁。活动标记只在actor结束、sink关闭与解绑请求返回后清除。

复现旧的空闲退出分支后，`exit_gate_rejects_open_registered_after_exit`断言失败；恢复修正后通过。门闩测试包含100次登记/退出线程交错，但它们是纯测试，不代表真实应用压力已经通过。

## 实例验收准则

| 场景 | 实际触发与必须独立核对的证据 |
| --- | --- |
| 快速切换 | 媒体库先准备B，再用真实卡片事件A→B→A；每次只等打开请求开始，不等准备完成。原生命令开始/结束时间必须证明至少两个打开请求重叠，最终选中、DOM、Rust owner和token都属于最后A。 |
| 准备中退出 | 点击A后观察真实在途打开，调用应用正常退出。第一次ExitRequested的门闩快照必须记录opening>0，而不仅是退出前的采样；最终opening=0且退役数覆盖在途请求。 |
| 播放中退出 | 实际设备时钟推进超过250ms后调用应用正常退出；不提前发source close，也不强杀进程。最终actor结束、decoder被回收、sink关闭、原生表面解绑。 |

三类场景各用两个独立进程重复，采用生成的受控素材和独立应用数据目录。只允许debug、`--mcp --mcp-hidden --mcp-validation --native-preview-host --native-source-preview`组合。原生音频仅静音自身WASAPI会话，不改变系统音量、设备或用户工作区。

打开/控制记录来自原生命令入口，仅验证场景启用，保留有界元数据和单调时间戳；不替换Tauri只读的内部invoke，也不模拟成功响应。外部runner另存运行前源码/程序/前端产物哈希、退出码及子进程PID和创建时间。后代进程采样可能漏过采样间隔内的短进程，因此同时核对解码器自己的join/reap记录；采样不被称为完整进程事件跟踪。

## 覆盖限制

源profile探测目前不在每个FFprobe步骤中检查取消；退出会等待正在执行的有界准备收尾。每次探测10秒的上限不是全部准备或驱动调用的总退出时限。实际短素材退出耗时不能证明所有异常设备都能在同样时间退出。

程序退出、Present返回和静音设备时钟不证明可见屏幕或扬声器的物理音画同步。这一轮也不涵盖多轨混音、长片/高分辨率持续负载、跨屏DPI、系统挂起、强退恢复或安装包验收。

## 本轮结果

六个独立隐藏实例已通过，三场景各两轮；独立脚本从原始记录重算并验证，而不是只读取应用的`ok`字段。

| 场景 | 主进程PID | 结果 |
| --- | --- | --- |
| 快速A→B→A | 46264、13376 | 各有3个打开请求实际重叠，初始B加三次切换共4个请求全部退役；两个过时打开返回不支持，最终A可播放，初始与最终actor均清理。 |
| 准备中退出 | 5204、33048 | 第一次退出门闩观察opening=1，退役计数0→1，最终opening=0；均在actor创建前结束准备，不冒充设备初始化每个阶段的取消覆盖。 |
| 播放中退出 | 45304、29712 | 原生时间推进超过250ms时正常退出，退出前没有显式关闭当前token；actor、解码线程/子进程、sink、child与DComp解绑证据完整。 |

全部主进程退出码为0；六轮源码、程序、前端产物及生成素材身份一致。独立报告位于`src-tauri/target/native-source-validation/stress-45471f91-52c2-4bcc-89bc-1df963697ce4/stress-verification-c22d89af-1a76-4133-96de-301cd0a6e4fd.json`，`ok=true`、`complete=true`。原始命令记录最多128条，溢出明确使验证失败，已通过“先登记129个在途调用再完成”的计数回归，不会把证据截断当成完整压力通过。

同一程序另跑基础9步骤回归：播放、暂停、定位、自然EOF、片尾重播、精确末尾、切源与兼容回退全部通过；主进程32972退出0。独立报告位于`src-tauri/target/native-source-validation/controls-regression-228a7db9-f2c7-46af-b78f-44819a047809/source-verification-634571a0-5dad-4aa5-8c2e-5bbced544a1f.json`。

工程检查：前端273项通过；Rust默认102项通过/6项忽略，原生feature294项通过/8项忽略；lint、前端构建、格式与原生构建通过。忽略项不计作通过。正确的独立验证构建命令为`cargo build --locked --features native-preview-host,tauri/custom-protocol --bin kaicut`（在`src-tauri/`执行），必须先有`pnpm build`产物。

保留的失败与观察限制：首批`stress-73222520-917f-44ef-b10b-c027808908a8`漏掉`tauri/custom-protocol`，产物指向未运行的开发服务器，DOM检查超时，未进入播放，不计成功。独立核验也曾因把可空的进程路径当必填、只按PID忽略创建时间复用而拒绝数据；相关失败JSON保留。PID26592在原实例退出之后被另一个`cmake`进程复用，最终CIM创建时间证据确认并记录复用，没有干预该进程。部分已退出短进程的ExecutablePath不可用，PID、创建时间和父链证据保留。

六轮stderr均出现WebView内部`Chrome_WidgetWin_0`注销警告1412，不能称为完全无警告退出。KaiCut自有child注销与DComp解绑已独立通过；这不证明WebView内部警告的根因已解决。可见退出体验仍未验收。
