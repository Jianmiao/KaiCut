# M3 Windows 导出实现与验收

日期：2026-10-11。当前已接入真实编码，尚不是完整发布验收。

## 用户流程

1. 点击导出，选择新的 MP4 保存位置；未保存项目也可独立选择输出路径。
2. 检查时间线、素材链接、编码器编译支持和输出路径。已有文件、目录、源素材、无效文件名不允许作为输出。
3. 点击开始导出：Rust 复核预检、保存不可变快照、启动后台 FFmpeg。后续编辑和切换项目不会改变该任务。
4. 导出窗口显示真实进度，可以收起并继续编辑，重新打开后查看任务。
5. 取消先请求停止，进程退出、临时文件清理后才显示已取消。应用窗口在导出或取消过程中不能关闭，须先取消或等待完成。
6. 本次运行失败/取消任务可使用同一快照重试，也可根据当前剪辑新建导出。重启后的历史只读，不自动续导出；上次未完成任务标记已中断。

## 成片规则

| 项目 | 当前行为 |
| --- | --- |
| 预设 | 1920×1080 SDR，项目有理数帧率，H.264 MF 8 Mb/s + AAC 192 kb/s、48 kHz 双声道 |
| 视频 | 项目轨道顺序中第一条未隐藏且覆盖当前帧的视频轨优先；画面等比缩放并补黑边 |
| 空隙与图片 | 空隙输出黑场；图片按片段时长重复，透明部分压到黑色，不透出下面的视频轨 |
| 视频原声 | 仅随当前可见的视频片段输出；被遮挡或隐藏的视频片段原声不参与混音 |
| 独立音频 | 音量、静音、源入点、淡入淡出使用同一快照；线性淡化与预览整数帧增益一致，导出按音频采样连续计算 |
| 混音 | 两条音频轨与视频原声直接相加，不自动归一化，不带限幅器；多路大音量可能削波 |
| 范围 | 最多 64 个项目片段、64 个展开的解码输入；长路径达到命令行预算时明确失败 |
| 能力边界 | 无变速/转场/关键帧/HDR 色彩处理，无音画自动关联，无批量任务队列；当前仅 Windows |

2026-10-16 起查看器明确分为素材预览和时间线预览：时间线按播放头、首条未隐藏视频轨及独立音轨解析，选中下层片段不改变合成；素材模式只播放选中源文件。两端共用一份测试夹具核对画面优先级、源时间与淡化增益。WebView 时钟/解码/缓冲不等于 FFmpeg 离线渲染，不承诺所有 VFR/MOV、长时同步或所有设备帧级一致。

2026-10-16 回归修订：导出按包含像素比例的显示比例缩放，修复非方形像素素材被压窄及错误黑边；导出窗口修复迟到任务历史覆盖新建表单、切换项目被旧状态阻塞等竞态。完整后台导入、剪辑、保存重开、真实编码与可复查项目见 [WORKFLOW-REGRESSION.md](./WORKFLOW-REGRESSION.md)。下方 2026-10-11 的验证数量保留为该批次历史记录。

## 快照、进程与输出保护

- `snapshot.json` 和 `job.json` 位于 app-local `export-jobs/<jobId>/`，不修改 `.kaicut v2`。快照记录项目、输出路径、引用素材大小/修改时间和音频属性，不保存播放头、选择、URLs 或媒体字节。
- 只有本次运行在 Rust 内存登记的快照能执行。编码前后对比磁盘快照与内存副本，检查媒体指纹；重启不能把被修改的磁盘快照直接当作可运行任务。
- 使用固定打包 FFmpeg/ffprobe 和参数数组；路径不插入滤镜表达式。每个输入限定本地 file 协议和格式白名单；图片采用字面文件名，`%03d` 不会展开为图片序列。
- 进度从独立管道读取，错误日志限 64 KiB。取消轮询约 80ms；探测单素材超时 10 秒，整个预备探测预算 60 秒；编码总运行上限 24 小时。
- 编码器使用 Windows Job Object，在应用异常退出时终止。正常失败/取消通过资源回收清理临时 MP4 与滤镜文件。
- MP4 临时文件位于目标同目录，验证 H.264/AAC、1080p、48 kHz 立体声、精确视频帧数/帧率及时间线时长后同步并无覆盖发布；即便别的程序在导出时创建了同名目标，也不会覆盖。
- 强退恢复只清理记录中属于该 job 的普通临时文件，校验任务前缀、扩展名、规范化父目录并拒绝符号链接，保留原素材及最终成片。刚创建空临时文件、尚未来得及记录就崩溃的极小窗口可能留下空文件。
- 记录最多加载 500 个历史目录；磁盘不足由实际临时写入或 FFmpeg 失败报告。尚无提前空间预算和用户缓存清理页。

## Sidecar 来源

沿用 FFmpeg n7.1 / `b08d7969c550a804a59511c7b83f2dd8cc0499b8`，无源补丁；保持 LGPL-2.1-or-later，禁用 GPL、nonfree、version3、network，新增合成/混音滤镜及本地 pipe 进度协议。无 libx264/libx265 fallback。完整配方、SHA-256、许可与构建输出见 [BUILD-RECORD.md](../src-tauri/binaries/BUILD-RECORD.md) 和 [binaries/records](../src-tauri/binaries/records)。旧构建保留在 `E:/ffmpeg-build/backups/pre-export-2026-10-11`。

编码器列表只证明编译支持；当前机器的真实导出测试不能替代其他 Windows 设备的 MFT/驱动验证。对外分发仍需匹配源码交付与许可证据，Apache-2.0 不改变 FFmpeg 的 LGPL 条款。

## 自动验证与待验收项

- 前端回归：原生保存位置请求、预检失败、旧 revision 结果丢弃、快照只提交一次、后台编辑/重新打开进度、取消等待确认、同快照重试、重启历史不提供无效重试。
- Rust 回归：快照不可覆盖、修改检测、状态迁移、真实子进程终止、进度读取上限、取消/目标文件竞争、成功发布、错误流/缺帧拒绝、恢复清理保护。
- 渲染器环境测试实际执行应用 `render_plan`，验证有源入点的画面、黑场、波形 RMS、音量/淡化/静音和有理数帧率，输出还交给 worker 的同一验证函数。
- 没有控制用户桌面；本轮不声称 Tauri 窗口手动体验、干净机器安装、长时漂移、真实相机/VFR/HDR、磁盘耗尽和强退进程恢复全流程均已完成。macOS 待设备。

运行环境测试：`cargo test --locked --lib export_render::tests -- --include-ignored`。这些用例要求本仓库 Windows sidecar 与可运行的 Media Foundation 编码器；默认测试保留忽略标记以区别设备条件。
