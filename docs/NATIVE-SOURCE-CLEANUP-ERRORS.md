# 原生源预览清理失败

本批修正取消回执和预览表面解绑的错误处理。默认 WebView 播放器、编辑命令、项目格式、sidecar 和许可证不变；不操作可见桌面或系统音频设备。

## 修复内容

- 媒体线程的 Cancel/Finish 回执检查已记录的清理错误，不能仅因清理函数返回就回复成功。清理错误与原始播放错误分别保留。`finish()` 仍等待线程退出并返回完整报告，供运行时判断是否可回退。
- 已取消的音频输出不再继续投喂或忙轮询，即使 Stop 失败使“可能仍运行”标志保持为真。取消清理未确认时 Observe 不再次读取失效设备；正常取消后仍保留真实设备时钟观察，供旧媒体回归验证。
- 原生表面解绑先执行隐藏/暂停并取得状态，成功后才清除绑定记录。任一步失败保留原 Weak 身份；即使强引用已经消失，也不允许新绑定覆盖未确认的释放。旧 sink 的关闭不会清除新 sink。
- 前端释放整个子表面后，关闭确认还必须检查已有的 `lastCleanup`。绑定为空但历史释放失败、缺失 `closed` 或仍有子窗口，都不能作为安全回退的依据。最终退出若已没有子窗口，会保留上次实际释放结果；窗口消失不再使失败证据丢失。

## 验证层次

Stop/Reset 用可控输出后端验证：失败时仍尝试解码器关闭，保留设备可能运行和缓冲未重置的状态；重复取消不得抹去失败记录，也不能继续播放。这些是软件契约测试，未令真实系统设备失败。

隐藏应用场景 `unbind-failure` 在实际解绑事务的 suspend 调用之前注入一次错误。记录失败前和事务返回后的真实绑定，验证首次与重复关闭报错、选 B 时仍被原失败 token 阻止、没有 HTML 或原生第二播放器。前端错误态可能正常释放整个子表面，必须用原始 child 清理记录证明该释放，不能仅凭 child 为空宣称成功。随后走正常应用退出。

此注入没有调用失败的 COM API，不是驱动故障或设备拔插验收。原生解绑、子窗口最终释放与失败 token 的保守保护是不同事实，报告分开保存。
