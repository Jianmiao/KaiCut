# KaiCut 项目任务与里程碑

- **状态**：规划稿 v0.1
- **原则**：先验证能力，再扩大范围；每个里程碑必须有可运行的验收证据
- **平台范围（2026-10-06 更新）**：当前没有 Mac 设备，M0–M5 只针对 Windows 交付与实机验收。macOS 适配/截图/性能/签名公证在获得设备后另立验收，不阻塞当前工作；Linux 继续延后。
- **当前阶段**：用户于 2026-10-06 已授权初始化空壳；只实施五区布局、单文件 JSON 新开存、媒体元数据导入、主题与占位组件。以下 M0–M5 的其他目标继续保留为后续任务，不代表已完成。

## M0：能力探针与范围锁定

### 目标

确认 Tauri 2 是可行基线，锁定 P0 的时间基、媒体格式、项目文件方案和 FFmpeg 构建合规边界。

### 任务

- 建立 Windows 的代表性硬件、系统、WebView2 和 GPU 测试矩阵；macOS 测试矩阵待设备后建立。
- 验证 Tauri shell、Rust ↔ React typed IPC、FFmpeg/ffprobe sidecar 的启动、事件、取消和崩溃恢复。
- 用真实 1080p CFR、VFR、长 GOP、可变音频采样率和损坏媒体做 probe、seek、缩略图和波形探针。
- 固定 P0 媒体矩阵：MP4/MOV、H.264 8-bit、AAC/WAV/MP3、44.1/48kHz、24/25/29.97/30/50/60fps，并覆盖旋转 metadata、单双声道和不支持格式错误。
- 验证时间基、帧率、drop-frame/non-drop、音频主时钟和导出快照规则。
- 评估 Windows Media Foundation/D3D/WASAPI 的 helper 或 FFI 路径。
- 固定 LGPL-only FFmpeg 版本、构建配置、许可证清单和第三方编解码器审查项；默认 LGPL-2.1-or-later，排除 GPL/nonfree/version3-only 组件。
- 第一阶段决定 `.kaicut` 单文件 JSON 的 schema v1 和迁移策略；目录包作为后续兼容版本，不进入本次空壳。

### 验收标准

- Windows 干净构建可以打开测试窗口并正确启动、停止 sidecar。
- 至少一段代表性视频可完成首帧、精确 seek 和音频输出探针，并记录误差。
- M0 记录明确的 Tauri 继续条件；若关键能力失败，记录 Electron 切换决定与范围影响。
- 当前许可证、Windows 签名和日志脱敏风险都有负责人和下一步；macOS 公证明确列为待设备后的独立事项。

## M1：项目基础与媒体资产

### 目标

完成项目中心、项目文件 v1、媒体导入和可恢复保存。

### 任务

- 定义项目中心、新建、打开、最近项目和项目路径错误流程。
- 定义同一项目被外部修改、同时打开和锁文件冲突时的重新加载、另存为和保留当前编辑策略。
- 实现 `.kaicut` 单文件 JSON v1、保存、基础 schema 校验和未来目录包迁移预留。
- 建立媒体资产索引、元数据、缩略图、基础波形、离线状态和重新链接流程。
- 设计缓存目录和清理策略，确保缓存不可用时仍能打开项目。
- 设定缓存占用显示、最低剩余空间阈值、自动清理和导出目标已存在时的版本化/确认策略。
- 为媒体、项目文件、恢复和导入错误建立可读的日志与状态文案。

### 验收标准

- 导入视频、音频和图片不会阻塞界面，失败项不会阻止其他素材继续处理。
- 强退后可以恢复最近一次有效编辑；临时文件或损坏缓存不会覆盖有效 manifest。
- 移动原始媒体后，项目显示离线并能通过重新链接恢复，不静默绑定错误文件。
- manifest schema、迁移和缓存删除测试通过。

## M2：时间线与预览核心

### 目标

完成 P0 基础多轨编辑闭环，并让音视频时钟、时间线渲染和键盘操作达到基线。

### 任务

- 完成 2V + 2A 轨道模型、片段选择、移动、裁切、分割、删除、吸附、锁定、静音。
- 完成命令历史、撤销/重做、成组音视频编辑和时间码输入。
- 实现 DOM/ARIA + Canvas/OffscreenCanvas 混合时间线、视口裁剪和波形缓存。
- 实现预览播放、暂停、逐帧、拖动定位和基础音频监听。
- 完成 FFmpeg 代理或 `<video>` fallback，并记录原生硬件路径的可行性结果。
- 补齐弹层焦点、键盘导航、时间线语义和非拖拽操作。

### 验收标准

- P0 编辑操作可通过鼠标和键盘完成，且中文输入不会误触时间线快捷键。
- 10 分钟代表性素材音视频漂移小于 1 帧；seek 误差不超过 1 帧或 1ms。
- 1000+ 片段测试夹具可选择、滚动、缩放、拖动、撤销；播放头和编辑交互达到 60fps 目标，达不到时有明确降级记录。
- Windows NVDA 能读取轨道、片段名称、时间范围、选择、锁定和静音状态；VoiceOver 列入 macOS 后续验收。

## M3：导出、任务和快照

### 目标

完成可恢复的 H.264/AAC 导出流程，并验证导出与后续编辑相互隔离。

### 任务

- 定义默认 1080p H.264/AAC 预设、色彩范围和音频采样率；先确认 LGPL 构建/运行环境提供可用编码器，缺少时报告该预设不可用，不假设 libx264 软件回退。
- 实现不可变 `snapshot.json`、导出 job 目录、队列、进度、取消、失败、重试和临时文件清理。
- 处理磁盘空间不足、sidecar 崩溃、编码器不可用和部分输出文件。
- 关闭项目或应用时明确提示任务处理方式；强退后的任务标记为 interrupted，不承诺后台续导出。
- 在 Windows 验证 FFmpeg sidecar 参数、路径、权限和签名打包。

### 验收标准

- 导出提交后继续编辑不会改变当前任务的输出。
- 取消不会留下可被误认成完整成片的文件；失败展示原因并能重试。
- 磁盘不足和 sidecar 崩溃都有可操作的恢复路径。
- 代表性媒体的导出在 Windows 验证播放器中可打开并保持音视频同步。

## M4：Windows 稳定性与质量门

### 目标

让 Windows P0 流程达到可发布状态，完成性能、无障碍、签名和降级验证。

### 任务

- 接入并验证 Windows Media Foundation、D3D11/12、WASAPI；在 LGPL 可用能力内验证软件降级。
- 验证低性能、无模糊、减少透明度、减少动态效果和高对比度模式。
- 覆盖 100%、150%、200% 缩放，窗口调整、面板折叠、键盘布局和文件路径差异。
- 完成 Windows 代码签名、SmartScreen 观察、安装/卸载和升级演练。
- 运行代表性项目、长时间播放、VFR、离线媒体和异常退出回归测试。

### 验收标准

- Windows P0 用例通过，硬件不可用时已声明的软件降级路径可工作。
- NVDA、键盘、减少透明度/动态效果和高对比度用例通过。
- Windows 签名、安装、升级、卸载和干净机器启动通过。
- 没有影响项目打开、编辑、保存或导出的 P0 性能或稳定性阻塞项。

## M5：发布候选与交付

### 目标

形成可复现、可回滚、可支持的 Windows 发布候选版本。

### 任务

- 锁定版本、构建环境、依赖清单、FFmpeg license notices 和源码获取说明。
- 完成项目 schema 迁移、旧版本打开、恢复、升级和回滚测试。
- 完成崩溃日志脱敏、诊断导出、用户可见错误文案和支持流程。
- 生成 Windows 发布包，保留产物哈希、签名和实机验收证据。
- 将 Linux 维持为实验性技术分支，不把它混入 P0 发布承诺。

### 验收标准

- 干净机器可以安装、启动、创建项目、编辑、导出、升级和卸载。
- P0 没有未接受的 blocker；所有已知限制都记录在发布说明。
- 构建可复现，二进制、sidecar、helper 和依赖许可证清单可追溯。
- 性能、媒体、恢复、签名和无障碍回归报告可交付给发布评审。

## 风险与规避任务

| 风险 | 规避任务 | 关闭条件 |
| --- | --- | --- |
| LGPL FFmpeg 构建与编解码器专利 | 默认 LGPL-2.1-or-later，禁用 GPL/nonfree/version3-only 组件，排除 libx264/libx265；记录 buildconf/-L/编码器、依赖 BOM、对应源码与补丁，独立评估专利 | 实际构建证据和 notices 通过；当前未携带二进制，不能声称已通过分发验证 |
| 时间线性能 | 视口裁剪、独立播放头层、波形 LOD、Canvas/DOM 混合、1000+ 片段夹具 | 达到 M2 性能门槛或有已批准降级 |
| Tauri WebView 差异 | 当前聚焦 Windows WebView2；避免逐帧 IPC；保留未来平台边界 | Windows M0/M4 关键交互通过；macOS 后续单独验证 |
| 音视频同步 | PTS/timebase、音频主时钟、VFR/重采样/丢帧测试 | 10 分钟漂移与 seek 误差达标 |
| 原生硬件路径不可用 | capability matrix；在已审查 LGPL 构建内验证解码降级，单独验证编码能力 | 没有可用 H.264 编码器时禁用预设并说明；其他格式须显式选择并经过 Windows 验证；macOS 后续单独验证 |
| macOS 签名与公证（延期） | 获得设备后再执行 helper/sidecar/dylib 与 app 签名、公证、权限和干净机测试 | 作为后续 macOS 发布门槛，非当前 Windows M4/M5 门槛 |
| 数据丢失与恢复 | 原子写入、上一份 manifest、autosave、journal、job snapshot、迁移测试 | 强退、磁盘不足、缓存损坏测试不丢最近有效状态 |
| 路径和权限差异 | 当前验证 Windows 文件占用、权限、中文与长路径；保留 Rust 统一路径层 | Windows 重新链接、保存、导出通过；macOS 安全范围资源后续验证 |

## 下一步执行顺序

1. 先确认 P0 的 2V + 2A 轨道上限、默认 H.264/AAC 1080p 预设和 `.kaicut` 目录包方案。
2. 收集一组可再分发或已获授权的测试媒体：CFR、VFR、长 GOP、不同采样率、损坏文件和 10 分钟同步样本。
3. 执行 M0 能力探针，优先验证 Tauri/WebView、FFmpeg sidecar、精确 seek、时间线渲染和原生路径可行性。
4. 同步完成 Windows LGPL FFmpeg 构建、编解码器、专利、签名和安装验证清单；macOS 签名/公证暂缓。
5. M0 通过后再初始化应用工程；若关键探针失败，重新评估 Electron，而不是在未验证的 Tauri 基础上继续堆业务范围。
