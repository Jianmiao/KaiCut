# Windows 原生音频时间映射验证

本轮承接 [解码兼容性验证](NATIVE-COMPAT-PROBE.md)，验证音频与视频具有不同源起点时的 PCM 映射，并使用非周期音频降低重复正弦掩盖错误偏移的风险。实现范围是独立、显式运行的 decoder-only 探针；不更改 UI、项目格式、MCP 或主应用播放器，不创建声卡、GPU 或可见窗口。

## 时间与样本规则

视频时间零点来自实际首个解码画面的 PTS。音频源 PCM 的第 0 帧对应实际首个解码音频帧的 PTS，不能直接用首个编码包 PTS 或容器声明起点代替。AAC priming/skip samples 由解码器处理后，映射层不能再裁切一次；实际 PCM EOF 帧数也不能仅由容器 duration × sample rate 推断。

音频相对视频的偏移为“音频首个解码帧时间 − 视频首个解码帧时间”，保留符号和有理数时基。每个请求区间拆成明确的前置静音、连续源 PCM 和尾部静音，采用左闭右开边界；分段长度之和必须恰好等于请求输出长度。早于音频起点和达到实际 PCM EOF 的部分填充零，不能省略它们使输出时间缩短。早于视频起点的源音频则通过正向 PCM 源偏移裁去。

时间差保留带符号有理数，查询选择“纳秒向下取整后的 PTS 不大于目标”的最后一个源采样帧，再按整数采样数推进本块；前置静音按输出网格向上取整。不能先分别转换成浮点秒再相减。无法表达、溢出或超过限额的输入显式失败。负时间差不等于非法数据，但负源采样索引不能传给解码器。

当前 `span` 是单个区间起点查询，最多返回 4800 音频帧的组成。连续播放时必须保存并推进整数采样游标，不能对每块独立重新量化时间后就声称无缝传输。纯模型接受 8–192kHz、最多 24 小时源 PCM；本轮真实素材仅验证 48kHz 双声道。

AAC 内容继续从起点顺序解码，再按 PCM 样本位置裁切；本轮不提供压缩音频快速随机定位。独立探针将计算出的有效源区间交给真实 `StreamingDecoder`，与完整顺序解码的参考 WAV 按样本比较；静音段由映射结果明确生成并验证。

## 素材和验收

- 使用已审计的仓库 LGPL sidecar，不替换编码器。
- 非周期双声道 PCM、零起点 AAC、偏移封装 AAC，各自建立完整解码参考；AAC 的有损输出只与同一源的完整 AAC 解码比较，不与编码前 PCM 要求逐样本相等。
- 视频分别使用真实零起点和非零起点文件。音频起点以实际探测结果为准，不根据 `-itsoffset` 或 `-output_ts_offset` 的输入参数声称恰好偏移 2 秒。
- 目标覆盖音频开始前、开始边界前后、中段、源音频尾部边界及 EOF 后；跨越边界的请求同时核验静音长度、有效 PCM 起点和输出总长度。
- 纯模型验证带符号时基运算、分段、边界和溢出；真实解码验证内容、源帧数、队列限额和子进程回收。增加错位样本负对照，确认参考信号能暴露偏移错误。
- 保留源、参考、固定程序及源码摘要，失败报告与运行参数。旧 24 项兼容矩阵和 HD 设备数据属于历史结果，本轮只在实际重跑后记录新的回归结论。

## 实际素材与负对照

素材批次 [fixtures-d924c584](../src-tauri/target/native-audio-timing-validation/fixtures-d924c584-e159-44f3-b1d0-678e34c76cd2/audio-timing-fixtures.json) 的原始元数据已核对：

| 音频源 | 首个解码帧 PTS / 时基 | 实际解码 PCM 帧数 |
| --- | --- | ---: |
| 非周期 PCM | 0 / 48,000 | 480,000 |
| 非周期 AAC | 0 / 48,000 | 480,256 |
| 偏移封装 AAC | 94,944 / 48,000，即 1.978 秒 | 481,280 |

生成命令请求偏移 2 秒，但偏移文件实际首解码帧位于 1.978 秒，PCM 长度及摘要也与零起点 AAC 不同。两者必须使用各自完整解码参考，不能仅对同一 PCM 人为加 2 秒标签。视频源实际起点为 0 与 30,720 / 15,360，即 2 秒。

[素材独立核验](../src-tauri/target/native-audio-timing-validation/fixtures-d924c584-e159-44f3-b1d0-678e34c76cd2/fixture-verification.json) 包含 3 类音频各 4 个窗口、每窗 4096 音频帧的负对照。源起点为第 72,480、144,000、144,960、341,904 帧；全部 12 个窗口在故意错位前后各 1 帧或交换左右声道后，F32LE 摘要均与正确窗口不同。这证明这些受测窗口可检出对应偏移/声道错误，不把有限窗口检查扩大为全样本无歧义保证。

## Rust 映射与解码结果

[原始报告](../src-tauri/target/native-audio-timing-validation/batch-3e191524-4c35-439d-bf2e-3c17a5fe32d7/run-8afba767-4648-4c91-8930-a77138e3405a/native-audio-timing-validation.json) 的 87 个窗口及 3 次完整音频解码通过。三个音频源分别与两个视频起点组合，基础目标之外追加每组实际音频起点、结束点及其前后 1ns/一个采样周期附近的位置；负的项目时间目标不进入请求。

每窗输出恰好 4800 个双声道音频帧，87 窗合计 417,600 帧。其中有效源 PCM 为 201,613 帧，前置静音 9603 帧，尾部静音 206,384 帧，三者之和与输出总长一致。54 窗含真实源 PCM，33 窗完全静音，14 窗同时包含源 PCM 和边界静音。源内容、交错双声道输出及左右声道摘要均记录；独立时基映射核验另行汇总。

实际偏移 AAC 与 2 秒起点视频组合时，音频相对起点为 -22ms；项目时间 0 对应源第 1056 个音频帧。这里的裁切来自实测音视频起点差，不是重复扣除 AAC priming。与零起点视频组合时则保留 1.978 秒前置静音，两种方向均有受测窗口。

3 次完整解码分别读取 480,000、480,256、481,280 帧，与各自完整参考一致。54 次有效源区间解码加上 3 次完整解码，共 57 次 decoder 启动；纯静音窗口不启动解码器。所有自有子进程和 reader 完成关闭，最大显式关闭耗时 8.904ms；音频/视频队列高水位分别为 8 块/4 帧，未超既有上限。完整音频 EOF 验证的是音频子进程正常结束，辅助视频可在音频完成后主动关闭，不能称为该视频完整播放。

## 最终核验与限制

[独立验证汇总](../src-tauri/target/native-audio-timing-validation/batch-3e191524-4c35-439d-bf2e-3c17a5fe32d7/verification-summary.json) 以另一份 BigInt 有理数计算重新推导源起点、各窗口的分段及采样位置，并从参考 WAV 重算输出和左右声道摘要；3 次完整源解码、87 窗、静音段和 12 个负对照均通过。验证还核对实际解码音频 PTS 连续性、总采样数、源/参考身份和回收记录，没有仅比较原报告里使用同一映射结果得出的两个摘要。

本轮也重新运行 [既有 24 项解码兼容矩阵](../src-tauri/target/native-audio-timing-validation/batch-3e191524-4c35-439d-bf2e-3c17a5fe32d7/run-02fef0ee-532f-4ad5-8df9-f1224f364013/native-compat-validation.json)，全部通过并经独立复核。[固定程序与源码身份](../src-tauri/target/native-audio-timing-validation/batch-3e191524-4c35-439d-bf2e-3c17a5fe32d7/build-context.json) 保留本批实现身份；不把上一轮 HD 设备结果当作本轮新结果。

[工程检查记录](../src-tauri/target/native-audio-timing-validation/batch-3e191524-4c35-439d-bf2e-3c17a5fe32d7/verification-checks.json)：前端 lint、231 项测试、构建通过；默认 Rust 100 项通过、6 项既有环境测试忽略；audio-timing 探针 48 项、compat 探针 40 项、stream 探针 99 项通过，各有 2 项既有专项默认忽略。探针复用模块测试，三个数字不能相加宣称独立覆盖。两个本轮 release 探针构建、格式及 diff 检查通过。记录中的解码进程 PID 引用可能被系统复用，结束时按对应进程身份核查无 FFmpeg/ffprobe 或探针残留；本轮未另跑旧 ignored 项或设备测试。

解码内容正确不代表实际声卡播放或物理音画同步；本轮不创建声卡/GPU、不作实时播放资格认定，也不替换主应用播放器。下一步需要实现保持整数采样游标的连续传输，再单独验证设备供音和真实呈现。
