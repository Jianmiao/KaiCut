# 原生源预览故障处理

本批继续验证Windows显式开发开关下的单源播放器。默认WebView播放器、时间线编辑、项目文件及导出不变。所有真实实例使用隐藏窗口、独立应用数据目录和生成素材，只静音自身音频会话，不控制桌面或修改系统设备。

## 问题与修正

- 暂停或就绪状态下，原媒体线程只等待控制请求，不主动发现解码子进程失败。现在在空闲检查点读取解码状态与子进程非零退出；即使视频队列已满、reader尚未读到EOF，也能发现失败。正常退出码0和仍在队列中的尾帧不算故障，播放中的供给路径保持原检查机制。
- 解码失败与清理失败原先混在同一错误字段中。`DecoderShutdown.cleanupErrors`单独记录释放/等待错误，原始解码错误继续保留。已完成join/reap的故障报告可以完整交给上层；真实清理失败及第一次关闭结果会保留，重复关闭不会变成空报告的假成功。
- 若原生关闭无法确认，保留失败会话身份并阻止再开播放器；恢复需要重新启动应用。原始素材解码失败且已确认释放资源时，仍允许兼容回退和重新选择素材。

## 验证边界

| 场景 | 触发与证明 |
| --- | --- |
| 定位中切源 | 在实际秒数输入触发seek后选择B，独立核对原生命令时间区间真实重叠；B从零开始，旧响应不能把A的状态写回来。 |
| 暂停时解码失败 | A实际播放后暂停；终止此会话持有句柄对应的`stream-rgb`私有子进程。无外部PID输入、不修改源文件。等待原生释放与兼容播放器出现，再选B恢复原生播放。 |
| 设备初始化失败 | 真实解码器建立后、WASAPI打开前注入一次错误，确认解码线程/子进程收尾和初始化线程join，再回退并选B恢复。没有实际禁用设备，不能宣称真实设备拔插或驱动故障已验证。 |

注入只允许debug和显式隐藏验证参数组合，且仅触发一次；普通运行与release不能启用该路径。进程与清理必须依靠原始证据，故障actor允许保留原始错误，但`cleanupErrors`必须为空。页面与原生窗口状态不是屏幕截图，也不证明可见刷新、听感或物理同步。

## 实际结果

三种场景各两个独立隐藏实例通过。正式批次：`src-tauri/target/native-source-validation/faults-4b2e19fa-3d05-4363-8188-c02fbc0e6925`；独立报告`fault-verification-4a1d1dec-3ff2-482f-afc8-cbb18131d92d.json`为`ok=true / complete=true`。

| 场景 | 主进程PID | 原始证据与结论 |
| --- | --- | --- |
| 定位中切源 | 43668、18904 | 1.75秒定位与B打开实际重叠316.2755ms、334.2366ms。A定位因旧表面卸载返回`Media surface has been closed`，属于切换取消，并非定位成功；取消错误、匹配token、重叠区间和确认清理均保留。B从零开始并实际播放超过300ms。 |
| 暂停时解码故障 | 33924、30064 | A播放后暂停，终止自身`stream-rgb`句柄，退出码1；actor保留原始错误，reader受队列背压时其error字段可以尚为空，不能编造reader报错。原生资源确认释放后出现一个HTML播放器；选B可恢复原生播放。 |
| 设备初始化注入 | 10812、20192 | 单次注入发生在真实解码器已创建、WASAPI尚未打开时；三个解码子进程回收、初始化线程join，兼容回退后B正常原生播放。`actualDeviceOpenAttempted=false`，不是物理设备故障通过。 |

独立脚本逐项核对源码、程序、前端产物、四份checkout/可执行目录sidecar和素材哈希；六轮身份一致。全部主进程退出0，原生线程、解码进程、sink、child及DComp退场有证据；所有`cleanupErrors`为空，原始故障没有被抹掉。另对报告的58个内存变体做负例校验，残留播放器、未join/reap、缺少重叠、清理错误伪装为解码错误等均被拒绝，没有修改真实报告。

同一程序完成基础9步骤回归（PID42936）和旧受控媒体路径回归（PID46052）：EOF、重播、定位、兼容回退及旧路径42次Present、5次诊断帧像素/四段PCM核对通过。证据分别位于`target/native-source-validation/faults-controls-9ec48589-8f0f-4d73-8ad2-3bfcbd4b726c`与`target/native-tauri-media-validation/faults-regression-23ddeb17-dde4-489d-8010-c3bbde72ef01`（均相对`src-tauri/`）。

工程检查：前端282项通过，Rust默认102项通过/6项忽略，原生feature313项通过/8项忽略；lint、前端构建、Rust格式与嵌入前端的原生构建通过。忽略项不是通过项。相关红绿测试分别复现暂停故障未上报、关闭重试丢证据和资源未确认却返回关闭成功，再验证修正。

## 保留的失败与后续范围

前一批`faults-81d899d4-b110-451b-aab9-7e05b0a19c9e`保留：首个seek运行已恢复B，但验收器误把预期取消当成失败；修正后的接受条件只允许同一旧token、精确取消错误、真实重叠和完整清理，其他错误不豁免。该批解码故障实例的WebView子进程在主进程退出后的首次检查仍在，之后自行退出；新runner最多等待10秒并记录实际等待，不强杀或忽略残留。最终正式六轮在这一有界规则下通过。

六轮仍记录WebView内部`Chrome_WidgetWin_0`注销警告1412；KaiCut自有child/DComp清理通过不等于此警告已修复。进程采样可能漏掉短进程，关闭账本另行核对；不将采样称为完整系统事件追踪。

本批没有注入真实的Stop/Reset/解绑失败，不能称为实际设备异常验收。后续已完成profile探测与哈希取消，并用真实解绑后的确认错误注入验证阻止重复播放器的路径，见 [NATIVE-SOURCE-CANCELLATION.md](./NATIVE-SOURCE-CANCELLATION.md)；设备初始化/actor准备和真实驱动故障继续独立推进。
