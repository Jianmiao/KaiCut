# 原生源预览近片尾启动压力验证

本批延续欠载诊断，固定四个独立隐藏实例，每个实例六次定位到片尾前200ms并播放到自然结束，共24次启动。保持播放器、缓冲参数、剩余帧判断不变，不注入延迟，不以跑到通过为结束条件。

通过实际DOM定位输入与播放按钮执行，每次先确认相同媒体token、新source epoch、新segment编号、准确目标及未启动状态，再观察该代次自然片尾。初始段加六个定位段共七段，低于现有八段保留上限；最终还要求所有视频事件和解码器关闭记录完整，不允许历史被环形淘汰后仍宣称完整验收。

实验完成与零欠载分开报告。出现欠载也继续完成固定次数并保留原始事件；遇到解码、资源清理或证据缺失则明确失败。只验证本机隐藏实例，无桌面输入、真实听感、可见画面或物理同步验收。

## 结果

2026-10-18，四个独立隐藏实例（PID35532、45052、46224、39560）均完成六次自然近片尾启动，共24次，记录欠载数为0。没有追加次数直到通过，也没有注入音频延迟。每实例保留七段、82条完整视频事件，没有触及八段/128事件上限；六个seek均有独立代次和解码器退休记录。

| 指标 | 本批观察 |
| --- | --- |
| Adapter Start调用耗时 | 1.6991–4.7294ms |
| Start返回至首次供音观察 | 0.0984–0.2155ms |
| 首泵设备padding | 576或1056帧 |
| 设备容量与格式 | 1056帧、48kHz双声道，约22ms |
| 每尾段实际接受采样 | 9600帧，即200ms |
| 欠载事件 | 24次启动均为0 |

首泵时间包含GetCurrentPadding查询耗时；Start时间指适配器调用而非单独COM API；设备接受采样也不是扬声器输出时间。不得将这些观察换算成物理同步、无听感断音或硬实时保证。

## 判断

本机、同一短素材的24次近片尾启动未复现旧偶发欠载。不能据此抹去更早失败、认定根因已修复，或推广到长素材和其他设备。

后续不同定位跨度验证已记录在[20 秒跨度压力验证](./NATIVE-SOURCE-SPAN-STRESS.md)和[59 秒跨度压力验证](./NATIVE-SOURCE-LONG-SPAN-STRESS.md)：各自最终构建的两轮固定序列均完成，仍没有复现自然欠载。继续扩大代表性分辨率、素材和设备矩阵，保持诊断和失败保留；真实设备故障、可见画面、听感和跨设备性能仍独立验收，不切换默认播放器。
